## 4 · Decisions taken without the user this wave

Five, each recorded because nobody was asked and each is reversible only at a cost.

1. **§D.9 was ANSWERED, as option (a), BY THE WAVE ORCHESTRATOR — not by the maintainer.** §D is
   the section of decisions the maintainer owes, and this one was taken on the row's own written
   recommendation because the alternative was a lane that could not finish. It is the most
   consequential thing in this wave: **a run that folded nothing and said it worked now fails.**
   The cost is priced and accepted in the row — a run fails where it succeeded before **iff no
   member of the barrier succeeded** out of a fan that planned at least one, under
   `onBranchError: "skip"` as much as `"fail"`, in all four modes. Unchanged and pinned: a PARTIAL
   loss folds; a degraded branch whose earlier member wrote folds; a fan whose branches all succeed
   writing nothing folds; an EMPTY fan folds and succeeds (§A.47). Reversing it is one predicate
   and one test file. **If the maintainer wanted (b) or (c), this is the decision to revisit first.**
2. **§A.64's rule replaced the row's literal ask with a stronger one, and reversed two intermediate
   refusals.** The row asked for stack IDENTITY on the `joinDepth + 1` arm; what shipped is that
   plus "a node inside a fan-out may be named by at most one join", and the arithmetic the row
   named is gone. Two graphs that intermediate cuts REFUSED now compile — a branch split across two
   disjoint joins, and a held join in a sibling fan's barrier — because each was measured to fold
   every contribution exactly once. **Refusing a working graph to protect an ordering nobody
   declared is the trade this rule does not make**, and the comment that disclosed the refusal as a
   trade is gone with the refusal. Ambiguity (`fanoutEdgeStack === undefined`) with ONE claimant
   stays legal, which is `empty-fanout-oversight.test.ts`'s router shape and the whole licence the
   tolerance ever had.
3. **§A.63 FAILS THE RUN rather than journaling a refusal row, and only for the run's own
   identity.** Failing is the stronger of the row's two options and the one that needs no new
   journal vocabulary: `#failRun` and `errorRecord` already exist, so the `run.failed` row carries
   the refusal's own `details`. **Identity is the PAIR — `graphHash` AND the resolution manifest —
   and it is NOT recomputed**, which is the part a reader will want to re-litigate.
   `run.compiled.graphHash` is the FIELD the submitter supplied, not a hash this engine computed,
   so recomputing `graphHashOf(spec)` on one side compares two different things and declines every
   run whose submitter hand-built a `RunGraph` with a stale field — **which is precisely the §A.63
   shape, and the only shape that can reach a vocabulary refusal at all**, since the compiler
   stamps the field and refuses both faults. That was built, run, and measured red before it was
   declined. Two things ride with the decision: the gate doors (`resolveGate`, `decideGateBatch`)
   still throw unjournaled **on purpose** — a typo'd `--graph` on an approve is not a dead run —
   and the residue the pair leaves is §A.66.
4. **§A.61 puts TWO lists on the gate row, not one.** `readsUnresolved` alone answers *"this LOOKS
   like a handle — is it one?"* and cannot answer *"this does NOT look like a handle — WAS it
   one?"*: after a successful fetch the value carries nothing saying it came from outside the
   journal, so an empty `readsUnresolved` is the same document for a gate that read every handle
   back as for a gate that had none. Their UNION is the fact a `jq` reader needs, and it is
   recoverable only if both are named. On the ROW and not inside a value, for §A.58(1)'s reason:
   JSON keys are arbitrary strings, so every marker a value might carry is one a node can write.
5. **§H.10's flag loop drives ONE value for every flag, not a table of which flags are paths.** A
   table is a second list to keep in step with `KNOWN_FLAGS`, and this file's whole subject is
   three lists drifting apart; the next flag that resolves its value as a path would re-open the
   defect in silence. The loop's property is unchanged — the value's content never mattered to
   "must not be refused as an unknown flag", only that it is a value — and `--workspace` and
   `--data-dir` are dropped from the base argv when they are the flag under test, so no name
   reaches `parseArgs` twice. Pinned as a DIFFERENCE (`existsSync` before and after) rather than an
   absolute, so a directory an earlier run left behind cannot hold the assertion hostage.
