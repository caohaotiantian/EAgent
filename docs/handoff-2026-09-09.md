## 3 · Decisions taken without the user, still in force

- **A `RUN_FATAL_CODES` guard belongs at every `childUnavailable` site spanning a child drive.**
  Two exist, at `#runSubgraph` and `#resolveGateAsSystem`; a run-fatal code out of the child's drive
  is no longer re-classed. Any future site ending in `advance(childRunId)` needs the same guard —
  the criterion is written at the F site in `run/engine.ts`.
- **Merges run from the main checkout by a separate merge agent**, never from inside a lane
  worktree, and every merge re-verifies `git merge-base <target> <branch>` rather than trusting the
  lane.
- **A read counts as a read only where the executor unconditionally evaluates it** — node-level
  `reads`, `${…}` in tool args, a fanout edge's `over`. **Edge conditions never count**, on
  CLAUDE.md's "when a guard cannot decide, it fails closed". Cost, accepted: an exam whose only read
  is in a `when` is refused and the operator must add a real read.
- **Process hygiene, now a standing lane rule.** No unbounded `until … sleep` loops (macOS zsh has
  no `timeout`); every `node --test` carries `--test-timeout=<ms>`; every background process a lane
  starts is killed by that lane before its final message; reviewers work read-only in the lane's
  worktree rather than in one of their own.
- **A lane's report is written to disk BEFORE its final message**, so a lane that dies is still
  legible. Where the harness refuses the write, the final message is the report and somebody else
  persists it.

## 5 · Facts you would otherwise rediscover

- **`npm test`'s count is not the number of tests that ran.** A file whose bodies hijack
  `process.stdout.write` can report `ℹ tests 1` with the first test neither passed nor failed.
- **macOS zsh has no `timeout`.** `timeout 60 …` produces empty output that reads as a hang.
- **SIGTERM is deferred while `zsh` sits in `sleep`**, so `kill` looks like it did nothing; use
  `kill -9`. A loop you cannot reliably signal is a loop you cannot reliably stop.
- **`isolation: "worktree"` branches from the repository's DEFAULT branch, not from `HEAD`.** The
  symptom is a worktree with a pre-rewrite tree — `src/`, `tui/` — and no `packages/core/`. Verify
  your merge-base before you commit.
- **`git worktree remove` needs `git worktree unlock` first** when a live `claude` pid holds the
  lock ("cannot remove a locked working tree, lock reason: claude agent … (pid …)"). That pid is the
  process that spawned the lane agents, not a running build, so unlocking is safe once the lane is
  merged and verified.
- **Copy a lane's `.agent/<lane>/` out before removing its worktree** — `git worktree remove`
  deletes it.
- **`git merge` run from inside a worktree merges into THAT worktree's branch.**
- **`git archive <sha> | tar -x -C <dir>` is the cheap base proof**, one extraction per lane.
- **`git branch -a` marks a branch checked out in another worktree with `+`.** `+ init` is a second
  checkout, not a merge state.
- **A clean merge shows no files.** `git show --name-only --format='' <clean-merge>` prints nothing,
  so a path filter is blind to one — A0.26, closed at `c8aad7d`: the census reads `-m` now.
- **The binary refuses after source edits, and `npm run check` does not test that.**
  `scripts/verify-binary.mjs` is a CI `binary` job step; `check` includes neither it nor
  `build:binary`.
- **Drive a guard's TRUE arm before you defend it.** Substituting `if (false) throw e` for a guard
  and finding every test still green is how four rounds of argument became a deletion.
- **A row's stated mechanism is a hypothesis** — reproduce it before you cite it in the fix. One
  row's named mechanism (`plans['valueOf']`) was unreachable; the real defect was one object over.
- **A lane's `STATUS: CLOSED` is about the lane, never about its `TODO.md` row.**
