### §A.37 — three changes, and three divergences from the design it was handed

The design was quoted verbatim into 2026-09-15b §Repros as "the next wave's contract". All three
changes landed; **all three moved under review**, and the divergences are the part worth carrying.

**(1) The design's "Change 1 needs ZERO existing tests updated" was wrong, and it was wrong for a
reason that repeats.** It was derived by grepping four reason strings across `packages/core/test/`
— which cannot cover the SPLIT of arm `f`, because that arm's string was not one of the four.
`compensation-fires.test.ts:441` asserts exactly §A.37's shape 3. Measured after change 1 alone:
`3906 / 3905 / 1`. It now asserts `not_attempted` + `retryable: true`; **the claim that test is
about is untouched** — `world.purged` is still `[]`, so a run's own failure still approves no
irreversible undo.

**(2) Change 3 DROPS the design's `s.undo !== undefined` conjunct, which TIGHTENS beyond the
design and newly refuses a rewind the base accepted.** `planCompensation` strips `undo` from a step
it marks `unknown_tool` or `unknown_compensation`, so a hard-to-undo effect whose undo tool is
missing from THIS registry **and** whose arguments were never recorded arrived with the identical
signature — `steps 1`, `dispatch 0`, `blocked 1`, nothing settled — and was CROSSED, at the base and
at `c6f24b51` both: the charge hidden, the money gone. It is now refused. The direction is the one
`CLAUDE.md` allows, and **the refusal clears**: register the undo and the same journal is accepted,
`dispatch 1`, `refunds [42]`, `charges []`. Pinned as `SHAPE 2's SECOND DOOR` and its CONTROL. This
is a real behaviour change beyond what the design asked for and it is recorded as such — §4.2.

**(3) The B1 discriminant is a module-private `WeakSet`, NOT the typed `error` the design
specified — and a reviewer proved the typed one forgeable.** The design said to give
`#invokeTool`'s gate arm the same typed `err.policy(E_HUMAN_APPROVAL_REQUIRED)` its `deny` arm
returns, and to split on the code. But `#invokeTool` hands back whatever `tool.execute` produced
after a `postTool` REPLACE filter, and `err` and `CODES` are **public exports**: so a compensation
tool that RUNS, moves the money, and then answers with the floor's own class and code was recorded
`not_attempted, retryable: true`, left unsettled by `planCompensation`, and **dispatched a second
time by the operator's rewind — `refunds` `[42]`, then `[42, 42]`**. `retryable` is the field that
decides whether an undo runs again, so handing its value to the thing being undone is the whole
hazard in one line. It is now `APPROVAL_FLOOR_REFUSALS`, a `WeakSet` of the gate arm's own result
objects: unforgeable (identity; the object never reaches a hook or a tool), trap-safe (`has` calls
no proxy trap and answers `false` for a non-object — the settling direction), and holding no
durable state, so a restart that hands it back empty switches no guard off. The typed `error` was
dropped as dead. Re-run by this settlement as a mutation, §Repros.

Two more, smaller: **`#rewindSerially`'s message branches on `undo === undefined`** (the second
review found one sentence about missing `details` false for the half with no `undo` at all —
`#rewindPlanOf` computes `argsDigest` as `step.undo === undefined ? undefined : detailsOf(...)`, so
that half has none whatever the journal holds), and **both `retryable` docstrings were rewritten**,
in `journal/events.ts` and `run/compensation.ts`, to one rule: *set when the blocker is a fact about
THIS PROCESS or THIS TRIGGER; absent when it is a fact about the JOURNAL or the MANIFEST.* **The
verb asymmetry is noted and NOT closed** — it is §A.74.
