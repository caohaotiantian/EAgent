## 0. Orientation — read these before writing a line

The design is a *sibling of `trace`*. Internalize the existing pattern first:

- `src/extensions/trace.ts` — **the pattern to mirror exactly**: `activate(e)`
  returns a never-throwing dispose closure; every `e.on(...)` handler is
  `safe()`-wrapped; `registerCommand` is read-only; disposers collected in an
  array and torn down in a `try/catch` loop (`trace.ts:88-96`, `:98-173`,
  `:252-260`).
- `src/providers/mock.ts` — **how usage is produced**. Critical fact for the
  tests: `MockProvider` usage is **NOT a scriptable field**. `MockTurn` carries
  only `{text, reasoning, toolCalls}` (`mock.ts:26-31`). Usage is *computed*
  deterministically: `inputTokens = estimateTokens(systemPrompt) + Σ
  estimateMessage(messages)`, `outputTokens = estimateTokens(turn.text)`, where
  `estimateTokens(s) = ceil(s.length / 4)` (`mock.ts:96-99`, `:121-122`). It is
  emitted on the `done` event (`mock.ts:100`). **Do not modify the mock** (CLAUDE.md:
  the offline mock stays deterministic). Tests drive **known** token counts by
  crafting input/output **text lengths**, and assert cost as a **derived**
  figure (captured usage × price card), never a hard-coded dollar amount.
- `src/kernel/agent.ts:264-278` — the kernel sums `usage` into `#usage` and
  emits `usage` with `{ usage (delta), cumulative (running total) }`. `cost`
  reads both: the per-event `usage` delta drives the per-run figure, `cumulative`
  mirrors the session figure (design §5 Assumptions, mirroring `trace.ts:167-171`).
- `src/extensions/limits.ts:88-122` — the **defensive store-read** posture to
  copy for validating a `priceCard` override (numeric-coerce, fall back on
  anything malformed; design §8 "malformed priceCard").
- `test/helpers.ts` — `makeHarness({ responder, logger, ... })`. It builds an
  `Agent` on provider `"mock"`, model `"mock"`, with a fresh `MemoryBackend`
  store and a `silentLogger` (override via `logger:`). Activate the extension
  under test with `h.host.use("cost", activate)`; tear down with
  `h.host.unload("cost")`. `lastText(agent)` reads the last assistant text.
- `test/trace.test.ts:36-46` — the **command-output-capture idiom** (the live
  read surface for this suite): a local `runCommand(h, name, args)` that does
  `h.commands.get(name)` and invokes `cmd.run({ agent: h.agent, args, print:
  (l) => out.push(l) })`, collecting printed lines into an array to assert on.
  `h.commands` is the `CommandRegistry` the harness exposes (`helpers.ts:42`,
  `extension.ts:101`); the `CommandContext` shape (`agent`, `args`, `print`) is
  `commands.ts:10-16`. Reuse this verbatim shape for `/cost`. `test/limits.test.ts:83`
  shows the same helper used to **seed config through a command**
  (`/limits key=value`) before a run — the pattern T15 reuses for `/cost
  pricecard …`.

Kernel surface you will use (all existing — **no kernel change**):
`e.on("usage", ({usage, cumulative}) => …)`, `e.on("agent_start", ({input}) => …)`,
`e.on("agent_end", ({reason}) => …)`, `e.agent.model` (the price-card lookup key,
`agent.ts:114`/`:71`), `e.store.get<T>(key, fallback)` / `e.store.set(key, value)`
(`store.ts:13-14`; the store is already namespaced to `"cost"`), `e.registerCommand`,
`e.log.warn`.

## 2. Phase Breakdown — single phase: "cost extension (observability sibling of trace)"

The design is one cohesive observability consumer with no separable sub-feature
(the helpers, the handlers, the command, and the kill switch are interdependent
and share one file). **One phase**, TDD-ordered.

- Working tree clean on a feature branch (do not commit on `init`/default — branch

- `docs/design/2026-06-22-cost.md` read; §0 orientation files skimmed.
- No new files yet. You will create `src/extensions/cost.ts` and
  `test/cost.test.ts`, and modify `src/host.ts`.

### Design refs

Whole of `docs/design/2026-06-22-cost.md`. Hot spots: §2 Deliverables, §3 Scope
(NON-goals — do not exceed), §4 D1–D6 (decisions), §5 Dependencies, §7 Acceptance.

**T10 — TEST anomaly flag fires only on a gross spike past the min-sample guard.**
Business invariant: **"an anomalous run cost (`> mean + k·stddev`, `k=3`) is
flagged with `warn` exactly once, only after `N≥5` prior samples — and a normal
run, or a run below the min-sample count, never warns."** (design §4 D4, AC-4.)
Pass a custom `logger` to `makeHarness({ logger })` whose `warn` pushes to a
captured array. Seed the rolling window to ≥5 low-variance samples by **scripting
≥5 cheap identical runs** (the deterministic, reachable path — the harness
exposes no store backend to pre-seed the window directly, `helpers.ts:43`, and
the window is not command-settable; only `priceCard` is). Then run one whose
crafted output makes its cost ≫ `mean + 3σ`. Assert `warn` was called **exactly
once**, on the spike
run, naming the run cost vs the rolling mean. Add the converse asserts: (a) a
normal-magnitude run after seeding does **not** warn; (b) before `ANOMALY_MIN_SAMPLES`
(5) prior samples exist, no warn fires regardless of magnitude.
- Acceptance: `node --import tsx --test test/cost.test.ts` (FAILS, drives T11).

**T11 — IMPL `on("agent_end")` rolling window + anomaly warn.**
Add named constants `ANOMALY_K = 3` and `ANOMALY_MIN_SAMPLES = 5`. Register
`on("agent_end", safe(...))`: push the just-finished run's USD to a fixed-size
(e.g. last 20, §4 D3) rolling window persisted under `e.store` (defensive read of
the existing window; coerce/repair malformed entries). Compute mean + stddev over
the **prior** samples; if `priorCount >= ANOMALY_MIN_SAMPLES` and
`runCost > mean + ANOMALY_K * stddev`, call `e.log.warn(...)` with a message
naming run cost and rolling mean. **Warn-only** — never returns a decision, never
registers `beforeToolCall` (§3.2, §4 D6). Record last-run cost + mean for `/cost`.
- Acceptance: `node --import tsx --test test/cost.test.ts` (T10 passes).
  `npm run typecheck` exit 0.

**T13 — TEST `/cost` prints the four required blocks + the fallback marker, and
the live figure matches the derived cost.**
Business invariant: **"`/cost` reports session USD + token totals, the per-model
breakdown, the active price-card row(s), and the anomaly/baseline status; the
reported USD equals the derived `costOf` figure; and a run on an unknown /
`mock` model yields a finite USD figure whose per-model line is marked as a
fallback."** (design AC-1 live half **and** AC-2 **and** AC-7's rendered-output
half.)
After a run, capture `/cost` output via the local `runCommand(h, "cost", "")`
helper — it does `h.commands.get("cost")` and invokes `cmd.run({ agent, args,
print })` with `print` collecting lines into an array (the established
command-output-capture idiom, copied from `test/trace.test.ts:36-46`; the
`CommandContext` shape is `commands.ts:10-16`, and `h.commands` is the
`CommandRegistry` the harness exposes, `extension.ts:101`/`helpers.ts:42`). This
**command output is the only reachable live read surface** — there is no store
backend or `activate`-returned accessor exposed (`extension.ts:245-247`). The
harness model is `mock`, which prices at the fallback row, so this single run
exercises AC-1/AC-2/AC-7 together. Assertions over the captured lines:
`/cumulative/i` (session USD + tokens), the model id or `/per-model/i`,
`/price/i` (active card row), `/anomaly|baseline|mean/i` (anomaly status naming
mean + last run), **`/fallback|unknown/i`** (AC-7: the `mock`/unknown per-model
line carries the fallback marker). Then parse the USD number out of the
`/cumulative/i` line and assert **`Number.isFinite(usd)`** (AC-7: finite, never
`NaN`/crash) **and** that it equals the derived `costOf(captured.cumulative,
priceRow("mock"))` figure rounded to the rendered format (AC-1: the *live*
extension reports the same number T6 derives from the exported helpers — this is
where the running-extension behavior is pinned, against command output, not
internal state).
- Acceptance: `node --import tsx --test test/cost.test.ts` (FAILS, drives T14).

**T14 — IMPL the full `/cost` command (status form + `pricecard` setter).**
Register `/cost` via `e.registerCommand` (`name: "cost"`). Dispatch on
`ctx.args`:
- **Status form** (no args / unrecognized leading token → treat as status):
  read the closure-captured session state from T7 (*not* a re-derivation, so the
  rendered figures are exactly the ones the live T13 assertion checks against the
  derived `costOf`). Render four labelled blocks via `ctx.print`: (a) session
  cumulative USD + token totals, (b) per-model breakdown naming each model (mark
  fallback-priced models per AC-7), (c) the active price-card row(s) in effect,
  (d) an anomaly-status line naming the rolling mean and last-run cost.
- **Setter form** `pricecard <model> <inputPerMTok> <outputPerMTok>`: parse and
  **validate** the three args (model is a non-empty string; the two rates are
  finite numbers ≥ 0 — reuse the same defensive numeric coercion as the
  `priceCard` reader, `limits.ts:88-122`). On valid input, merge the row into
  the stored `priceCard` (`e.store.get("priceCard", {})` → set the row →
  `e.store.set("priceCard", …)`) so the change takes effect on subsequent
  pricing, and `ctx.print` the updated row/card. On bad input, `ctx.print` a
  rejection message and leave the card unchanged. This mirrors how `/limits`
  writes its own store config (`test/limits.test.ts:83`) and is the
  runtime-tunable knob (design §2, D1) and the seam AC-6/T15 seeds through.
  (`priceCard` only — keep `enabled`/threshold/mode store-backed unless a setter
  is trivially natural.)
Add the command's disposer to the dispose loop.
- Acceptance: `node --import tsx --test test/cost.test.ts` (T13 passes).

**T21 — IMPL register in `host.ts` adjacent to trace/limits.**

`import cost from "./extensions/cost.js";` to the import block and the
`["cost", cost]` entry to `BUILTIN_EXTENSIONS` next to the `["trace", trace]`

## 4. Data / Fixture Dependencies

- **Reuse `test/helpers.ts` `makeHarness`** for every live test. It provides the
  `Agent` (provider `"mock"`, model `"mock"`), a fresh `MemoryBackend` store, and
  `silentLogger` overridable via `logger:` (used by T10/T19 to capture `warn`).
  Use `lastText(agent)` (T12) and the local `runCommand` capture helper (copied
  from `test/trace.test.ts:36-46`) for `/cost`.
- **No external fixtures, no network, no temp files.** Unlike `trace-save`,
  `cost` writes no files — do not create a tmp dir. All state is in-memory store +
  bus.
- **Driving known token counts (design §7 note):** craft `responder` `turn.text`
  lengths to hit target `outputTokens` (`ceil(len/4)`); craft the run *input* (the
  `agent.run("...")` string, which becomes a user message) to influence
  `inputTokens`. **Always assert relative to the captured `usage` event**, never a
  hard-coded dollar bill (the mock cannot emit a round number).
- **Seeding the rolling window (T10):** script ≥5 cheap identical runs first,
  then the spike run. (Pre-`set`ting the window array directly is **not**
  reachable — the harness builds its own `MemoryBackend` internally and never
  exposes it, `helpers.ts:43`; only `priceCard` is seedable, and only through the

  choice in a test comment.
- **Seeding the `priceCard` override (T15):** invoke `runCommand(h, "cost",
  "pricecard <model> <in> <out>")` before the run — the command writes the
  validated row to `cost`'s namespaced store, the same self-configuration seam

  way to set `priceCard` from a test (the store backend is private and unexposed,
  and `host.use` surfaces no accessor, `extension.ts:245-247`).
