#### T4 — IMPL: the `ask` extension — tool + `ui:ask` gate + conditional grant + `ctx.ui.ask` call (D2, D6, AC 1, AC 7)

- Create `src/extensions/ask.ts`. Use `defineTool`/`ok` (`define.ts`),
  `ExtensionAPI` type (`../kernel/extension.js`). House rules: `.js` specifiers,
  strict TS, no `any`.
- `export default function activate(e: ExtensionAPI): () => void`:
  - **Kill switch first:** `if (process.env.EAGENT_ASK === "off") return () => {};`
    (mirror `recovery.ts:103`; satisfies T11 ahead of its test, fine — the test
    in T11 still drives the *assertion*).
  - **Conditional grant (D2):** `if (typeof e.agent.ui.ask === "function") e.grantCapability("ui:ask");`
    — grant only when the host UI can actually elicit, so an interactive run is
    not double-prompted and a non-interactive run leaves the capability
    ungranted (design D2; `api.agent.ui`, `agent.ts:68`).
  - Register the tool via `e.registerTool(defineTool({ ... }))`:
    - `name: "ask_user_question"`,
    - `capabilities: ["ui:ask"]` (D2),
    - `parameters`: object with `question: { type: "string" }`,
      `options: { type: "array", items: { type: "string" } }`,
      `required: ["question"]` (options optional — design §5),
    - `description`: concise — "Pause and ask the human a clarifying question
      before choosing a direction; supply options for multiple-choice. Use it
      when the instruction is ambiguous rather than guessing."
    - `execute(args, ctx)`:
      - read `question` (string) and `options` (optional `string[]`) from
        `args` with narrowing (no `any`).
      - **D6 / D5 branch:** `if (typeof ctx.ui.ask === "function") { const a = await ctx.ui.ask(question, options); ... }`
        else take the fallback (T6).
      - On an answer, return `ok(...)` whose content **contains the answer
        string** (e.g. the raw answer, or `Answer: ${a}`); when `ask` resolves
        `null`/empty, return the proceed-with-assumption fallback (T6/D5) so a
        `!rl` CLI does not dead-end (Risk §8).
- Track the tool disposable; `return` a dispose loop that `try/catch`es each
  disposable and never throws (T13/`todo.ts:128`).
- Acceptance:
  - `node --import tsx --test test/ask.test.ts` → T3's case now **passes**
    (GREEN).

> No new test file here — the CLI `ui` is an integration surface exercised offline

  ```ts
  ask: async (q, options) => {
    if (!rl) return null;                       // non-interactive → null (mirror confirm's `if (!rl)`)
    if (options?.length) {
      for (const [i, opt] of options.entries()) console.error(C.dim(`  ${i + 1}. ${opt}`));
    }
    const raw = (await rl.question(`${C.yellow("?")} ${q} `)).trim();

      const idx = Number(raw);
      if (Number.isInteger(idx) && idx >= 1 && idx <= options.length) return options[idx - 1]!;

    return raw;                                  // free text: "none of these, do Z"
  },
  ```

  empty → `null` so the tool's fallback handles non-interactive / garbage
  (Risk §8). House rule: `noUncheckedIndexedAccess` requires the `!` on
  `options[idx - 1]` after the bounds check.

## 3. Engineering Constraints Index

House rules (from `CLAUDE.md`) and conventions that bind every task above.

- **ESM + NodeNext, `.js` specifiers.** Import `.ts` files with a `.js`
  extension (e.g. `import { defineTool } from "../kernel/define.js"`,
  `import ask from "../src/extensions/ask.js"`). Required by
  `module: NodeNext` + `verbatimModuleSyntax`.
- **Strict TypeScript.** `strict`, `noUncheckedIndexedAccess`,
  `noImplicitOverride`, `noFallthroughCasesInSwitch` all on. **No `any`** — narrow
  `args.question` / `args.options` and `ctx.ui.ask` with `typeof` checks; use `!`

## 5. Regression Protection

The change is additive (one optional `UI` method, one new extension, one CLI
method). The following **must stay green** throughout and at exit — they prove no
existing behavior regressed:

- **`npm test` (full suite) exit 0** — the top-level gate. In particular:
  - **`test/cli.test.ts`** — the CLI host's `ui` object now carries an extra
    optional `ask`; the existing `confirm`/`notify`/`--json` behavior must be
    untouched (T15 adds a method, edits no existing line of `confirm`).
  - **`test/server.test.ts`** — the server still inherits `defaultUI`; no `ask`,
    so the absence-fallback path is the server's behavior (T16 makes no change).
  - **Any test constructing a `UI`** (via `helpers.ts` `autoUI`, or inline) —
    must still compile and behave identically because `ask` is optional (D1).
  - **`test/recovery.test.ts`, `test/capabilities` / capability tests** — the
    capability decision order is unchanged; `ask` only *uses* `grantCapability` +
    `require`, it does not alter them.
- **`npm run typecheck` exit 0** — the compile-time proof that the optional
  `UI.ask` breaks **no** existing `UI` implementer (`defaultUI`, CLI `ui`, server,
  `autoUI`) — design D1 / Risk §8.
- **`test/ask.test.ts`** — the new suite; all of AC 1–7 green (T3–T14).

If any pre-existing test goes red, the most likely cause is an accidental
non-optional type, an unconditional grant breaking a `deny` case, or a leaked
`EAGENT_ASK=off` env mutation — check those first.
