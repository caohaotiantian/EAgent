##### T1 (test): unit-pin the fixed schema and slug derivation

In `test/handoff.test.ts`, write unit tests for the two **pure** pieces the impl
will export (export them from `handoff.ts` so they are testable directly, as
`risk-guard` exports `parseVerdict` and `recovery` exports `recoveryHint`):

- **Business invariant — the handoff is a *fixed schema*, never free-form
  (design D3):** assert the schema-rendering helper (e.g. `renderHandoff(...)`
  or the fallback digest) emits **every** required section header in order:
  `## Goal`, `## Completed`, `## In progress`, `## Pending`, `## Files touched`,
  `## Commands run`, `## Open decisions`, `## Do not touch`, `## Next steps`,
  plus `## Reactivation`. (A fixed schema *is the point* — a resumer scans named
  sections instead of re-reading prose; free-form is `memory`'s lossy failure
  mode the design rejects.)
- **Business invariant — the filename slug is a stable, filesystem-safe excerpt
  of the run's goal (the first user message), so a handoff is identifiable
  without opening it (design D4):** assert the slug helper kebab-cases,
  lowercases, strips non-`[a-z0-9]` to `-` runs, length-caps (≤ 40), and maps an
  empty/whitespace first message to `session`. Cases to pin:
  - `slugify("Fix the login bug")` === `"fix-the-login-bug"`
  - `slugify("  ")` === `"session"` (empty → fallback; guards the empty-goal
    path in D4)
  - a long input is capped to ≤ 40 chars with no trailing `-`
  - non-ASCII / punctuation collapses to single `-` runs (e.g.
    `slugify("Refactor: auth & DB!!")` has no `:`/`&`/`!` and no `--`).

These are pure functions — no harness, no provider. Write the failing tests
first.

**Acceptance:** `node --import tsx --test test/handoff.test.ts` (T1 subtests
fail until T2; that is the expected red state).

##### T4 (impl): the `activate(e)` body — observer wiring, command, summarizer, writer

Extend `src/extensions/handoff.ts` with
`export default function activate(e: ExtensionAPI): () => void`:

- **Config** via `e.store` (design D6, mirror `risk-guard.ts:79-84`): an
  `enabled` boolean (default `false`), read together with the kill switch (T6
  wires the env read).
- **`summarize(messages)`** — the recursion-safe tool-less provider sub-call
  (design D2; copy `risk-guard.ts:96-137` / `compact.ts:184-202` in shape):
  `e.agent.providers.get()`, `provider.stream({ systemPrompt:
  HANDOFF_SYSTEM_PROMPT, messages, tools: [], model: e.agent.model, signal: new
  AbortController().signal })`, read the `done` message text; **fail open** to the
  T2 fallback digest on no-provider / throw / empty. Passing `tools: []` is the
  structural recursion guard (a tool-less completion cannot emit a tool call and
  re-enter any seam). Add a `let summarizing = false` re-entrancy boolean
  (`compact.ts:175`): the `agent_end` observer returns early while a sub-call is
  in flight, so a sub-call's own `agent_end` (if any) cannot recurse.
- **Writer** (design D4; copy `limits.ts:169-181`): `workspaceRoot()` =
  `EAGENT_WORKSPACE` resolved else `process.cwd()`; `dir = join(root, ".eagent",
  "handoffs")`; `mkdirSync(dir, { recursive: true })`; filename
  `<YYYY-MM-DD>-<slug>.md` with an `existsSync`-guarded monotonic suffix on
  collision (`…-2.md`, `…-3.md`); `writeFileSync(file, content, "utf8")`. Wrap all
  disk ops in try/catch that `e.log.warn`s and never crashes the run (R3).
- **`/handoff` command** (design D1, deliverable §2; `e.registerCommand`,
  mirror `risk-guard.ts:157-184`): bare `/handoff` writes now (always, regardless
  of `enabled`); `on`/`off` toggle the stored flag; `status` prints the current
  posture. The command prints the written path or a status line via
  `c.print(...)`.
- **`agent_end` observer** (design D1; `e.on("agent_end", …)`, payload
  `{ reason }`, fired in the loop's `finally`, `events.ts:20` / `agent.ts:235`):
  acts only when enabled (and not killed) and not already `summarizing`; reads
  `e.agent.messages` (the live transcript, `agent.ts:98`), summarizes, and writes.
  The observer **only reads** the transcript and writes a file — it never steers,
  follows up, prunes, or mutates context (design §3.4 non-goal).
- **No new capability, no `grantCapability`** — the only privileged action is the
  provider sub-call, which rides the agent's existing provider; writing under
  `.eagent/` mirrors `limits` and needs none (design §3.3).
- **Dispose:** return a closure that disposes the observer + command in a
  `for … try/dispose/catch` loop that never throws (copy `risk-guard.ts:186-194`).

- **Commit conventions** (project SKILL.md) — `feat(phase1): …` for the feature
  commit; `fix(phase1-roundR): <keyword>` for within-round fixes. Include
