#### Module shape to build (`src/extensions/compact.ts`)

Two **exported pure functions** (unit-testable, mirroring `prune.ts`'s exported
`pruneMessages`) plus closures inside `activate`. ESM with `.js` specifiers even
for `.ts` imports; strict TS, no `any`, no `noUncheckedIndexedAccess` violations.

Constants (pure, self-justifying per §4 D2/D4/D6):

- `const DEFAULT_BUDGET = 60_000;` (§4 D4 — sits above prune's 40k floor).
- `const DEFAULT_KEEP_TURNS = 3;` (§4 D4 — protect the last K=3 user turns).
- `const PIN_MAX_BYTES = 2_000;` (§4 D6, R4 — byte cap on the pinned block).
- `const PIN_PREFIX = "pin:";` (store-key prefix for pinned notes, mirroring
  `memory.ts`'s `NOTE_PREFIX = "note:"` at `:38`).
- `const COMPACT_SYSTEM_PROMPT` — a fixed prompt instructing the sub-call to emit
  **exactly** the three markdown sections `## Decisions`, `## Files`,
  `## Open threads`, and to **merge/preserve** any prior such sections present in
  the input (the D8 carry-forward instruction). The word "summar" must appear so
  the test's function responder can branch on it (`memory.test.ts:20`); the exact
  prose is a non-behavioral format choice (§4 D2).

Exported pure helper — **`tokenEstimate`** (§4 D1, the load-bearing divergence
from prune):

```
export function tokenEstimate(messages: Message[]): number
```

- Per-string estimator **identical** to prune's `est(s) = Math.max(0,
  Math.round(s.length / 4))` (`prune.ts:30-32`) — copy it verbatim; do NOT add a
  tokenizer (§3).
- Sum `est` over **both** `text`-block `.text` **and** `tool_result`-block
  `.content` across the **whole** transcript. This is the deliberate divergence
  from prune: prune sums **only** `tool_result` content (`prune.ts:64-69` skips
  non-`tool_result` blocks) because it is a tool-output *size* defense; `compact`
  is a *conversation*-size gate, so it must **also** count dialogue text — else a
  text-heavy conversation under-counts and never fires (§4 D1). (Other block
  types — `tool_call`, `thinking`, `image` — are not counted; only `text` and
  `tool_result`, the two the design names.)

Exported pure helper — **`splitIndex`** (§4 D1/D4, R3):

```
export function splitIndex(messages: Message[], budget: number, keepTurns: number): number
```

- Returns the index at which to split: messages `[0, idx)` are the foldable
  *older* slice; `[idx, end)` is the protected *recent window*.
- Walk **backward** counting `role === "user"` messages as user-turn boundaries.
  The recent window is the last `keepTurns` user turns (a user message plus the
  assistant/tool messages that follow it). The split point is the index of the
  `keepTurns`-th user message from the end — a **user-turn boundary** — so an
  in-flight `tool_call`/`tool_result` pair (assistant `tool_call` then `tool`
  `tool_result`, which follow a user turn) is **never** severed (§4 D1, R3,
  AC-4).
- If there is no user-turn boundary older than the last `keepTurns` turns (one
  giant turn — §5 assumption), return `0` (or a sentinel the hook reads as
  "nothing to fold"): `compact` is a no-op and `prune` handles size — acceptable
  per §5.
- This function decides *where* to split; the **budget gate** (whether to split
  at all) is `tokenEstimate(messages) > budget`, evaluated in the hook. Keeping
  the estimate and the split separable makes both unit-testable.

Closures inside `activate(e)`:

- `cfg()` — read each call (off by default, §4 D7, mirrors `risk-guard.ts:80`):
  - `enabled`: `process.env.EAGENT_COMPACT === "off" ? false :
    (e.store.get<boolean>("enabled", false) ?? false)` — **default `false`**.
  - `budget`: `e.store.get<number>("budget", DEFAULT_BUDGET) ?? DEFAULT_BUDGET`.
  - `keepTurns`: `e.store.get<number>("keepTurns", DEFAULT_KEEP_TURNS) ??
    DEFAULT_KEEP_TURNS`.
- A **module-level or closure re-entrancy boolean** (`let summarizing = false;`)
  — set `true` before the sub-call, cleared in a `finally` (the `risk-guard`/
  `memory` recursion guard, §4 D5). The hook returns the input unchanged if
  re-entered while `summarizing` is true.
- `pinnedBlock()` — concatenate all `e.store` entries whose key starts with
  `PIN_PREFIX` (mirroring `memory.ts:230-234`'s key scan), render as text, and
  **byte-cap** to `PIN_MAX_BYTES` (slice on a `Buffer.byteLength`/`Buffer.from`
  basis, not character count, so multi-byte content cannot overrun — §4 D6, R4,
  AC-5). Returns `""` when there are no pins.
- `async summarize(older: Message[]): Promise<string>` — the **recursion-safe
  tool-less sub-call** (§4 D5), copied from `risk-guard.ts:95-121` /
  `memory.ts:78-93`:
  - `const provider = e.agent.providers.get(); if (!provider) return
    renderFallback(older);`
  - `for await (const ev of provider.stream({ systemPrompt:
    COMPACT_SYSTEM_PROMPT, messages: older, tools: [], model: e.agent.model,
    signal: new AbortController().signal })) { if (ev.type === "done") finalText
    = textOf(ev.message); }`
  - `return finalText.trim() || renderFallback(older);` — fails **open** (no
    provider / throw / empty → deterministic digest), so the prefix is never
    dropped (§4 D5, R5, AC-12).
  - `tools: []` means the completion cannot emit a tool call and re-enter the
    loop (AC-11). Wrap the body so any throw also falls back.
- `textOf(message)` — concatenate text blocks (verbatim `risk-guard.ts:69-75` /
  `memory.ts:240-245`).
- `renderFallback(older)` — a deterministic, provider-free digest of the slice
  (mirror `memory.ts:252-268`), **non-empty** by construction (AC-12).
- `summaryMessage(summaryText)` — build ONE `system` message via `text("system",
  …)` and set `msg.meta = { source: "compact", kind: "summary" }` — the marker
  `prune` recognizes (`prune.ts:61`), mirroring `memory.ts:123-127`.

The **`transformContext` hook** (§4 D1/D8, AC-1/2/4/7/8/9):

```
e.hook("transformContext", async (messages) => { … });
```

1. `if (summarizing) return messages;` (re-entrancy guard, AC-11).
2. `const { enabled, budget, keepTurns } = cfg();`
3. `if (!enabled) return messages;` (off by default / kill switch already folded
   into `cfg().enabled`, AC-8/AC-9).
4. `if (tokenEstimate(messages) <= budget) return messages;` (under budget →
   untouched, no sub-call, AC-1). **Return the input array reference** so AC-1's
   "no summary inserted" holds trivially.
5. `const idx = splitIndex(messages, budget, keepTurns);` — if `idx <= 0` return
   `messages` (no foldable boundary, §5).
6. `const older = messages.slice(0, idx);` `const recent = messages.slice(idx);`
   — **`older` includes any prior `meta.kind:"summary"` message** at its head;
   do NOT exclude it (D8 carry-forward: it flows into the sub-call as input).
7. `summarizing = true; try { const summaryText = await summarize(older); }
   finally { summarizing = false; }`
8. Build a NEW array: `[summaryMessage(summaryText), ...pinnedMessages,
   ...recent]` where `pinnedMessages` is `[]` when there are no pins, else ONE
   message carrying the byte-capped `pinnedBlock()` text, positioned **after the
   summary, immediately before the recent window** (AC-5). Never mutate the input
   (`transformContext` operates on a copy already, `agent.ts:247-251`, but the
   contract is return-a-new-array).

The **`pin`/`unpin` tool(s)** (§4 D6, AC-5/6 — no capability, a private store
notebook like `memory`'s `remember`/`recall`, justified at `memory.ts:186-188`):

- A `pin` tool: params `{ key, value }` both required; writes `e.store.set(
  PIN_PREFIX + key, value)`; returns `{ content: \`Pinned "${key}".\` }`.
- An `unpin` tool: param `{ key }` required; removes the store entry via
  `e.store.delete(PIN_PREFIX + key)` (the `Store.delete` idiom, `store.ts:15`);
  returns a confirmation. (The design says "a pin/unpin mechanism (a tool or
  /compact pin)"; implement the tools, and additionally accept `/compact pin
  <key> <value>` as a convenience verb — see the command below.)
- **No `e.grantCapability`** (§3, §4 D6).

The **`/compact` command** owned by this extension (§4 D3, AC-9/AC-10) —
registered **after** `memory` so it shadows memory's `/compact` (last-wins,
`commands.ts:42-43`; restoring memory's on dispose, `commands.ts:31-39`):

- `name: "compact"`, a description distinct from memory's so AC-10 can tell them
  apart by `commands.get("compact")?.description`.
- Subcommands (no subcommand throws):
  - `on` / `off` → `e.store.set("enabled", true/false)`, print state.
  - `pin <key> <value>` / `unpin <key>` → write/remove a pin via the same store
    keys the tools use, print state.
  - `status` (default, no arg) → print `enabled`, `budget`, `keepTurns`, pin
    count.
  - `force` → compute `splitIndex` over `[...e.agent.messages]` and **print what
    a fold would do** (how many messages would fold, how many recent kept, pins
    retained) — even when the live transcript is under budget, *if* there is a
    foldable boundary. Do **not** call `summarize(older)` here: unlike
    `memory.ts:160` (whose force populates a cache its hook later consumes),
    `compact` keeps no cache, so a sub-call's summary would be computed and
    discarded — a paid model call with no effect on the transcript. The actual
    fold runs in the `transformContext` hook when the budget gate fires.

`activate` returns a **teardown** disposing the hook, the command, and the
`pin`/`unpin` tools in a loop that **never throws** (verbatim shape
`risk-guard.ts:170-178`).

## 3. Engineering Constraints Index

House rules (`CLAUDE.md` "House conventions" + the IMPL SPEC), all mandatory:

- **ESM + NodeNext.** Always `.js` import specifiers even when importing a `.ts`
  file (e.g. `import type { ExtensionAPI } from "../kernel/extension.js";`,
  `import { text, type Message } from "../kernel/types.js";`). Required by
  `module: NodeNext` + `verbatimModuleSyntax`.
- **Strict TypeScript.** `strict`, `noUncheckedIndexedAccess`,
  `noImplicitOverride`, `noFallthroughCasesInSwitch` are on. No `any` — model the
  types (use the `Message`/`ContentBlock`/`TextBlock`/`ToolResultBlock` types from
  `types.ts`). Index access is `T | undefined` — narrow it.
- **Zero runtime deps except `jiti`.** Pure Node only. The sub-call uses the
  existing `provider.stream` abstraction (not a new SDK); the estimator is
  `chars/4` (no tokenizer); the byte cap uses Node's `Buffer`. Do NOT add an npm
  dependency.
- **Capability gating.** The `transformContext` hook reads/transforms context
  only (no side effect) → **no capability**. The `pin`/`unpin` tools are a private
  `e.store` notebook (no filesystem/network) → **no capability**, exactly as
