### Phase 1 — the `todo` extension

**Design references:** `docs/design/2026-06-20-todo.md` §2, §4 D1–D6, §7 AC 1–8,

**Task list (TDD order — test tasks first):**

- **T1 (test): write/echo, replace, validation, render** in `test/todo.test.ts`.
  Load the extension via `h.host.use("todo", todo)` and call the `todowrite` tool
  through the registry (`h.agent.tools.get("todowrite")!.execute(args, ctx)` with
  a minimal `ctx` — copy the `ctx()` helper shape from `core-tools.test.ts:17-27`;
  `todowrite.execute` ignores `ctx` so a barer ctx also works). Invoke `/todos`
  **via the harness command registry**: `const out:string[]=[];
  h.commands.get("todos")!.run({ agent: h.agent, args: "", print:(l)=>out.push(l)
  });` (the exact idiom `flow-guard.test.ts` uses — `h.commands` is exposed by
  `makeHarness`). Each asserts the protected invariant (*the model and human
  see an authoritative, validated, canonical-format todo list*):
  - AC-2 (write+echo, exact D6 format): a 2-item write returns a non-error result
    whose content is exactly the D6 rendering — header `Todos (1/2 done):` then
    `- [ ] a (high)` and `- [x] b (low)` (assert the literal strings).
  - AC-3 (replace): a second write with a different list returns only the new
    list (old items absent).
  - AC-4 (invalid status, no mutation): a write with `status:"bogus"` returns
    `isError` naming `status` + the allowed values; a following `/todos` still
    renders the **previous** valid list.
  - AC-5 (invalid priority / empty content): `priority:"urgent"` and empty
    `content` each return `isError` naming the field.
  Watch fail (module absent).

- **T2 (impl): the extension** in `src/extensions/todo.ts`.
  `export default function activate(e: ExtensionAPI): () => void`:
  - Module/closure state: `let items: TodoItem[] = []` where
    `interface TodoItem { content: string; status: Status; priority: Priority }`,
    `type Status = "pending"|"in_progress"|"completed"|"cancelled"`,
    `type Priority = "high"|"medium"|"low"`.
  - `render(items)`: returns the **canonical D6 string** — `Todos (C/M done):`
    (C = count of `completed`, M = total) followed by one `- [<glyph>] <content>
    (<priority>)` line per item; `(no todos)` when empty. Keep a `GLYPH` map
    `{pending:" ", in_progress:"~", completed:"x", cancelled:"-"}`.
  - `validate(raw): {ok:true; items} | {ok:false; message}`: coerce `raw.todos`
    to an array; for each entry require a non-empty string `content`, a `status`
    in the Status set, a `priority` in the Priority set; on the first violation
    return `{ok:false}` with a message naming the field and allowed values; else
    `{ok:true, items}`.
  - The `todowrite` tool (`defineTool`, **no `capabilities`**, params
    `{type:"object",properties:{todos:{type:"array", items:{type:"object",
    properties:{content:{type:"string"},status:{type:"string"},
    priority:{type:"string"}},required:["content","status","priority"]}}},
    required:["todos"]}`): `validate` the args; on failure `return fail(message)`
    **without mutating `items`**; on success set `items = validated` and
    `return ok(render(items))`.
  - A `/todos` command (`e.registerCommand({name:"todos", description:"Show the
    current session todo list.", run:(c)=>c.print(render(items))})` — the
    `Command` interface requires `description`, so strict TS forces it).
  - `e.on("session_start", () => { items = []; })` and the same on
    `session_shutdown` (the `flow-guard.ts` reset idiom).
  - Return a disposer disposing the tool + command + the two event handlers.
  Make T1 green.

- **T3 (test): `/todos`, session reset, no-capability** in `test/todo.test.ts`:
  - AC-6 (`/todos` renders): after a successful write, `/todos` prints the D6
    list; before any write it prints `(no todos)`.
  - AC-7 (session reset clears): after a write, emit `session_start`
    (`h.agent.hooks.emit("session_start", {})`); `/todos` then prints `(no todos)`.
  - AC-8 (no capability, with control): use `makeHarness({fallback:"deny"})`,
    load `todo`, and a `MockProvider` responder scripting a `todowrite` call
    through `h.agent.run(...)`; assert the tool **executed** (its result is the
    rendered list, not a capability-denied error). **Control:** register a stub
    tool declaring `capabilities:["shell:exec"]` and script it in the same/another
    harness with `fallback:"deny"`; assert it **is** blocked (its tool_result is
    an error mentioning the capability) — so the `todowrite` success is
    specifically because it declares no capability.
  Watch the new ones fail (until T2 wires reset + the tool).

- **T4 (impl): wire + docs.** In `src/host.ts` add `import todo from
  "./extensions/todo.js";` and a `["todo", todo]` entry in `BUILTIN_EXTENSIONS`.
  Add a one-line `todo` entry to the `CLAUDE.md` extension inventory (a
  session todo list — `todowrite` + `/todos`, no capability). Run the full suite.
