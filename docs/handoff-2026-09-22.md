### §A.62 — a type is a property of a value, not of the rule that will read it

The row asked for one thing and the lane's hardest decision was a second thing the row did not ask.
`EDGE_FIELDS` is now
`Readonly<Record<string, {type: "string"|"count"|"stringArray"; readBy?: EdgeKind}>>`, the union
written inline so no type name joins the pinned surface, and the keys in their existing insertion
order so `unknownKeys`' `may declare \`a\`, \`b\`, …` fix stays byte-identical.

**The decision the row did not ask for: a wrong-typed field is refused on EVERY edge kind.**
`fanout-width-type.test.ts` asserted the opposite before this wave — `maxWidth: "banana"` on a `seq`
edge was deliberately not refused, "because refusing it here would be this rule deciding what an
unread field means". That test changed sides and says why. Two measurements settled it, neither of
them an argument: a MISSPELLED field on a `seq` edge was ALREADY fatal (`maxWidthh` is
`GRAPH020_UNKNOWN_FIELD`), so a wrong-TYPED one compiling clean was the asymmetry; and 60 rows of the
lane's 910-row census made `compile()` **throw** `CanonicalizationError: non-finite number` instead of
returning a diagnostic, every one of them a non-finite number in a field the edge's kind does not
read. No well-typed graph moved — `maxWidth: 4` on a `seq` edge still compiles.

**The layering that kept every existing suite green: the parse decides the TYPE, the rule keeps the
RANGE.** `isPositiveInt` was type AND range; moving the whole predicate would have turned
`maxIterations: 0` from `GRAPH006_UNBOUNDED_LOOP` into `GRAPH006_BAD_MAX_ITERATIONS` and dropped
`expansion.maxFanout` out of `GRAPH007_BAD_MAX_WIDTH`'s fix for `maxWidth: 0`. `count` therefore means
`Number.isSafeInteger` and nothing more, and every in-range and out-of-range NUMBER is byte-identical.

**Six fields are type-checked ELSEWHERE, and the set is named rather than assumed.**
`TYPE_CHECKED_ELSEWHERE` holds `id`, `from`, `to`, `kind`, `when`, `until`, each with the code that
refuses it in a comment, pinned by `edge-field-types.test.ts`. The default is to CHECK — a field added
to `EDGE_FIELDS` is type-checked unless somebody opts it out here, which is the fail-closed direction.
The residue is that the set is hand-written: if `GRAPH004_EXPR` ever stops being total over `when`,
the hole reopens silently, which is what the pinning test exists for. **And §A.78 is the proof that
"total" needed re-measuring**: `GRAPH004_EXPR` is total over `when` for a number, a `null` and an
object, and for an ARRAY the compiler never returns at all.

**THE BLOCKING DEFECT THE FIRST CUT CARRIED: `Array.prototype.every` skips holes.** `new Array(2)` —
a JSON-unreachable value, but reachable from any embedder building a spec in memory — passed the
`stringArray` tag, because `every` visits no index that was never assigned, and then threw
`CanonicalizationError: undefined array element at edges[2].branches[0]` from `digest`. The fix is an
index walk. The lane's own suite was green over it, which is the fifth wave in a row where that
sentence is the finding.

**The false correction, caught two rounds later.** Round 1 restored `GRAPH007`'s `expansion.maxFanout`
ceiling and wrote a docstring on `maxFanoutOf` claiming it read the ceiling member-for-member. Round 3
MEASURED it: `maxFanout: "24"` alone draws `GRAPH003_MALFORMED`; with `maxWidth: "24"` beside it the
compile prints `GRAPH007` ALONE, ceiling 32, because the new fatal suppresses the expansion refusal.
The clause was deleted and the suppression stated. **That suppression is also the scope of the
byte-identity claim**: `loom compile` is byte-identical to `6fb2e618` on all seven shipped fixtures
and on the wrong-typed fixture too, and on a MULTI-fault graph it is not — a racy graph plus a bad
`maxIterations` prints `GRAPH006` alone where the base also printed `GRAPH010`. A claim whose scope
was found by running is worth more than one asserted whole.

**Why it closes at TWO.** `readableFanoutWidth` in `run/engine.ts` stays hand-written, and the reason
is already written at the site: `Executor.attach()` is public and `RunGraph` is exported, so a graph
reaches the executor without having passed this build's compiler, and *"the compiler is the earlier
answer and the executor must not depend on having been the caller of it"*. Option (a) — export the

NOT renamed**, so the row's own grep keeps measuring something true: 6/4 → **4/4**, and the four left

### §A.76 — a preview releases what it installed, and the row's "not measurable" turned out to be wrong

`#planRollback`'s walk already threaded a `seen` set; the same input object now carries
`installed`, which `#childContextFor` adds to only when it BUILT a context and never when it found a
live one, and `planRewind`'s `finally` releases exactly those. That is the verb's own already-written
rule — *"a preview releases what it installed … only what THIS call attached: a run something else
holds on purpose is not this verb's to release"* — applied to the half it was not applied to. No new
vocabulary, no new code, no security door moved.

**Released with `#runs.delete`, not `#retire`, and the difference is a later verb.** `#retire` also
writes `#retiredRuns[runId] = graphHash`, so retiring a context the PREVIEW built would record the
preview's REBUILT graph as the graph that child retired with; `#retainedGraphOf` then compares it
against the child's own journal hash, and a child that had legitimately retired earlier with its real
graph would stop being re-attachable. A preview making a later verb worse is the exact shape this row
is about, so the release restores what was held before and nothing else.

**THE OBSERVABLE EXISTS, WHICH THE ROW SAID IT COULD NOT.** The row recorded that `#runs` has no
public membership predicate and `attach` returns `void`, so no assertion could distinguish "attached"
from "silently ignored". It can, through a later verb: a delegated child, previewed through
`planRewind(parent)`, then `attach(childRunId, correctedGraph)`, then rewound — the undo now
DISPATCHES (`compensation.recorded outcome: "compensated"`) where it was refused under the graph the
preview installed. **Two controls in the same fixture differ in ONE step each**, which is what makes
the first leg a measurement of the PREVIEW and not of `attach`: leg 2 is the same run with the
`planRewind` removed and it compensates; leg 3 is the same run with the `attach` removed and it fails
with the edited graph's own refusal.

**`#forgotten` needed two rounds and the second was a race.** `#contextFor`'s first act is
`this.#forgotten.delete(runId)`, so rebuilding a child context for a preview took back an explicit
`forget(childRunId)` and the release put the run back to "never seen" rather than to "explicitly
forgotten". Round 1 made `installed` a Map carrying the prior membership and restored it in the
`finally` — and review 2 found that the restore then overwrote an `attach` that LANDED DURING the
preview. Round 2's answer is not a re-read: `#contextFor` clears `#forgotten` **above** its early
return, so an `attach` on an existing context is itself an un-forget and the release can compare
identity and decline. Both halves pinned, and the grandchild leg at depth 2 pinned with them.

**`attach` was NOT made honest, and that is the arm not taken.** Replacing the graph of a LIVE
context would move the oversight floor, the capability allowlist and the compiled plans under a
running wave, and `#assertBound` runs on `advance`, not on `attach`, so nothing would catch it —
the loosening direction. Refusing has no code of its own and would have to be threaded past two
internal callers that attach right after `#contextFor` on purpose. **So `attach` on a live context
still discards the graph**, and whether the public door should say so is owed to the maintainer.

**One door tightened as a side effect, recorded because nobody asked for it:** a gate redelivered
against a forgotten-and-retired child now answers `E_RUN_NOT_FOUND` where it answered
`E_GATE_NOT_FOUND`. The run genuinely is not there; the older answer named the wrong absence.

**The engine lane's one (§A.77).**

- **§A.77 — a whole-count `k` above a STATIC, non-fan `branches` list compiles CLEAN and is refused
  only at the barrier, with every arm's writes already applied.** `GRAPH008_QUORUM_K` checks `k > 0`
  and, for `k > 1`, integrality; it never checks `k <= branches.length`. When every member is static
  and unfanned, that length IS the width before anything runs, so `k: 4` over three arms is a graph no
  input can satisfy and the compiler says `ok`. **The cost of catching it this late is in the channel**:
  all three arms ran, succeeded and applied their writes at the root coordinate first. *"Compiles,
  then fails at run time"* is what this project's compile stage exists to prevent. The REFUSING half is
  correct and stays — only the static half of the question is decidable, since a `conditional` edge
  narrows a static set at runtime (pinned) and a fanned member's width is data.

**§A.62's residue (§A.78–§A.81), all four found by probing rather than by reading.**

- **§A.78 — `when: [null]` exhausts the compiler's heap instead of producing `GRAPH004_EXPR`.** The
  mechanism took ten minutes to find and is worth the space, because it is a template: `lex` is handed
  the raw value, `src.length` is 1, `src[0]` is `null`, and **`null >= "0" && null <= "9"` is TRUE by
  numeric coercion**, so the number branch is taken; the digit regex declines `null` so `j` stays at
  `i`; `src.slice(i, j)` on an ARRAY is `[]` and `Number([])` is `0`, which is finite, so a token is
  pushed and `i = j` makes no progress. `out` grows until the heap is gone. It is a denial of service
  on `loom compile` reachable from a graph FILE, with no diagnostic and nothing naming the edge, and it
  is identical on `6fb2e618`. Its closing condition asks for a PROGRESS assertion rather than a type
  test, because any future branch that fails to advance `i` has the same shape.
- **§A.79 — a `subgraph` block with no `inputs` crashes the compiler with a `TypeError`** at
  `Object.entries(sub.inputs)`, `validate.ts:5094`. `SubgraphNode.inputs` is not optional in the type
  and `compile`'s input is a cast `JSON.parse`, so a graph FILE decides whether it exists. Its closing
  condition asks the same question of every other required sub-block `rule016Subgraphs` reads without
  checking, because a single `?? {}` closes one input and leaves its siblings.
- **§A.80 — a subgraph CHILD's edge `kind` is unchecked at compile.** `unknownEdgeKinds` lives in
  `compile.ts` and runs on the top-level spec only; `rule016Subgraphs` recurses `validateGraph`, which
  does not include it. So the ONE refusal that is total over `kind` — the reason
  `TYPE_CHECKED_ELSEWHERE` defers it — does not reach a child, and `kind: 42` in a child spec compiles.
  **PRE-EXISTING, and pinned NEGATIVELY** in `edge-field-types.test.ts`, which is the cheapest thing a
  lane can do with a defect in a file it does not own — the same move the 2026-09-19 CLI lane made on
  §A.75. The same probe shows §A.62's new parse check DOES recurse: the child's `maxWidth: "24"` is
  refused.
- **§A.81 — `POLICY_FIELDS`/`NESTED_FIELDS` are still NAME-only, and `maxIterations` has no executor
  copy.** Two halves of one shape, and the second is the one that costs a live run. `#assertBound`
  re-checks an unreadable `maxWidth` through `readableFanoutWidth` with a written reason — *"an
  unreadable one fans out zero branches in silence"* — and there is no equivalent for
  `maxIterations`: `#loopMayContinue` is a raw `w.task.iteration + 1 < (e.maxIterations ?? 1)`. A
  `RunGraph` reaching `attach` without this build's compiler therefore carries the bound straight in,
  and `maxIterations: {}` makes the comparison `NaN`, so **the loop stops after ONE pass, the
  conditional exit never fires, and the run reports `succeeded`** having done a seventh of its work.
  The same failure mode `readableFanoutWidth` exists to refuse, one edge kind over, failing OPEN.

**The port's three (§A.82–§A.84), each met by a stranger and not by a reviewer.**

- **§A.82 — the runtime's key-name redactor is narrower than a reasonable auditor's, and nothing warns
  that the two disagree.** It fails in BOTH directions and they need opposite remedies. UNDER-redaction
  is the worse half: `SECRETISH_KEY` needs an UNDERSCORE before the credential word, and the
  `QUALIFIED_WORDS`/`QUALIFIERS` fallback counts `token` only next to `api`, `access`, `bearer`,
  `signing`, … — `github`, `slack`, `registry` and `ci` are **not** qualifiers. So `GITHUB_TOKEN` is
  redacted and `GITHUB.TOKEN` is not. OVER-redaction is not cosmetic either: a key is hidden for what
  it is CALLED whatever it holds, so a gate cannot show an approver that a repair happened. **A wider
  regex is not the closure** — widening moves the gap and makes the over-redaction half worse; what is
  missing is a way for a graph to declare a per-key classification on a projection, in both directions.
- **§A.83 — `fs.read` appends its truncation marker INTO the returned content**, so a big document
  reads back as a syntax error in the FILE. `maxBytes` defaults to `200_000` and is compared against
  `text.length`, so it bounds CHARACTERS and not bytes. `details` carries `{bytes, truncated}` beside
  it, and a `tool` node writes only `content` to its channel. **The dangerous case is the one that does
  NOT break**: JSON happens to fail, which is why this surfaced at all; a format whose truncated prefix
  still parses hands a body a third of a document with no signal, and any workflow that searches for
  ABSENCES reads the missing part as compliance. Same shape at `proc.exec` and at `net.fetch`.
- **§A.84 — a `loop` edge is an edge to the scheduler and not to the compiler.** `validate.ts:364` and
  every analysis over `dagEdges`. It is NOT "include loop edges in `dagEdges`", which makes almost
  every looping graph look cyclic — the row's closing condition asks for the SET of analyses to be
  named first. And `rule021`'s `wouldCycle` depends on this exclusion list matching `ancestors`' one,
  four of its ten message arms turning on it (§A.73), so a change here is a change there.

## 4 · Decisions taken without the user this wave

Seven taken, and then the list of what was deliberately NOT taken, which is longer and is the more
important half.

1. **§A.75's unit is `contributed`, not arrivals.** A branch `onBranchError: "skip"` absorbed after an
   earlier member wrote still counts toward `k`. The alternative makes `skip` refuse a partial loss,
   which is what `skip` exists to accept. Reversible, and the pin that holds it is a two-node degraded
   branch added in round 1 — the first cut claimed the unit was pinned by its last test and it was not.
2. **§A.76 releases with `#runs.delete`, not `#retire`.** `#retire` records a graph hash, so releasing
   a preview-built context through it would make a child that had legitimately retired with its real
   graph un-re-attachable. Held by prose, not by a test: the lane measured that removing the choice
   leaves the suite green and said so rather than claiming a pin it does not have.
3. **`#contextFor` clears `#forgotten` ABOVE its early return**, which is a semantic change to a
   kernel method taken to fix a race rather than to add anything: an `attach` on an existing context is
   now itself an un-forget, so a preview's release can compare identity and decline. The alternative —
   re-reading `#forgotten` in the `finally` — loses to it because the read and the write are then still
   two steps apart.
4. **`readBy` says "declared for", not "read by".** Round 3 measured that `run/externalise.ts` reads
   `when`, `until`, `over` and `as` on EVERY edge kind and `checkCodes` reads `codes` on every kind, so
   "nothing reads it" was false; the advice the refusal gives survives because the arm fires only on
   values that already FAILED the tag.
5. **§A.62's executor copy stays hand-written**, and the row closes at two rather than being carried.
   Reversing it means either an exported predicate on a pinned surface or an executor that is only as
   safe as its caller.
6. **The port redacts its own projection SHAPE-ONLY, and `out/service.hardened.json` keeps the real
   value.** `was` and `report.hardened` carry `{redacted:"string",chars:7}` off the auditor's own
   `credentialKey`; the FILE keeps the credential, because it is the manifest and a credential the tool
   could not move behind a `secretRef` has to stay in it or the service loses its configuration. **What
   must not carry the bytes is the thing a person READS** — the gate listing and the markdown report.
   `now` stays in the clear deliberately, because hiding the `{secretRef}` would hide the repair.
7. **The port doc's F14 said "three reviews" over four enumerated rounds**, and this settlement
   re-counted it to FOUR in place rather than leaving a number nobody had run against the paragraphs
   below it.

**And these were NOT taken. Every one is owed to the maintainer, and four are owed for the fourth
wave running.**

- **§A.68 — `skip` vs `fail` on the shipped example.** Both modes now refuse a run below `k` and
  differ only in WHEN; which one the example should TEACH is the whole of what that file demonstrates,

## 5 · Facts you would otherwise rediscover

- **The weekly rate limit killed all three background agents mid-wave, and the recovery is a
  procedure.** One lane's review report had already arrived; a second reviewer produced NOTHING and had
  to be re-run from scratch; the third lane was mid-build. The orchestrator resumed each by MESSAGE
  after the reset rather than re-dispatching, which preserved their context. The cost is the reviewer
  whose work was lost entirely, and the lesson is the one already in the notes: reports to a durable
  place first, reviewers synchronous where they can be, and gate once per wave.
- **A lane wrote a DOCSTRING about another lane's semantics from that lane's file read at BASE.** The
  spec lane was asked to document `JoinNode.k`; it read `run/engine.ts` in its own worktree, which does
  not hold the engine lane's change, and wrote a sentence describing the BASE fold
  (`succeededWork === 0 && terminalWork === workMembers`) that the merged engine contradicts. Round 2
  rewrote it to the merged semantics, from the engine lane's statement of its own behaviour, with the
  commit body saying it was NOT reproduced by running. **The rule: a cross-lane fact must be stated by
  the ORCHESTRATOR, not read out of a worktree** — a worktree is a snapshot of the base plus one lane,
  and every other lane's behaviour in it is stale by construction. And a docstring a lane cannot run is
  a docstring that names the condition, the code, the case that flips and the pinning suite, and
  deliberately does not quote a message byte-for-byte.
- **THREE false corrections this wave, each caught by the NEXT reviewer, and the pattern is now four
  waves old.** The spec lane's `maxFanoutOf` docstring (false in both halves; the truth is that the new
  fatal SUPPRESSES the expansion refusal); the engine lane's claim that an unsatisfiable `k` is not a
  compile-time question (true for a conditional-narrowed set, false for a static one — and the
  correction deleted the true residue, which is §A.77); the port's *"already satisfied every rule this
  tool can repair"* (the fourth instance of the class its own F14 was enumerating, written into the
  sentence that replaced the third). `CLAUDE.md` says *reproduce by running, not by reading, including
  when correcting a comment*. **A round that corrects a claim must re-measure it, and the measurement
  must be pasted** — every one of these three replaced a false claim with a differently-false one, and
  every one was written by somebody who had just read the code.
- **A worktree was handed out based on `init` rather than `loom`, for the THIRD wave running.** The
  spec lane's branch was created at `086e47d2` and its plan records `git reset --hard 6fb2e618` as its
  first act. Check `git worktree list` immediately after dispatch, before a lane commits.
- **"Coverage of the guard is not coverage of the gap."** Two instances, one in each direction. The
  port added a `cell()` escaper and did not apply it to three fields, and the test that covered
  `cell()` was green — so a NUL still reached the report and `grep` called it binary, and the dotted
  keys that had just been routed there arrived unescaped. And the suite that "greps the artefacts for
  the secret" grepped `report.open` on ONE manifest: it was exactly as green as one that greps the
  whole gate listing and both files, which is what found `GITHUB.TOKEN`. **Ask what the guard does not
  see, and then grep for the BYTES rather than for the field you expect them in.**
- **When mutating a source file to prove a pin, mutate from a BACKUP — never `git checkout --` with
  uncommitted edits in the tree.** A fix round lost work to exactly that, and the recovery cost more
  than the measurement. `cp` the file, edit in place, run, `cp` back.
- **A reviewer must not share the builder's worktree**, carried forward because it held again: every
  review this wave ran from a `git archive` extract, and every blocking finding came from one.
- **`node --test packages/core/test/<dir>/` does not work in this tree** — it needs the glob,
  `node --test "packages/core/test/<dir>/**/*.test.ts"`. The bare directory form reports
  `pass 0 / fail 1` with a failure at `<dir>:1:1`, which reads like a broken suite and is not one.
- **A NAME-BASED anything cannot be audited by reading names.** §A.82's whole content. The redactor's
  regex and the workflow's regex are both readable and the gap between them is not: only running a key
  that falls in it shows you. The same argument is why `TYPE_CHECKED_ELSEWHERE` is PINNED rather than
  commented, and why §A.62's "total refusal" claims were re-measured field by field before the six were
  deferred.
- **`examples/.loom/journal.db` is gone.** It was untracked, gitignored litter from 10 Sep that three
