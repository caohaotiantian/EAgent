## 4 · Decisions taken without the user this wave

Five, each recorded because nobody was asked and each is reversible only at a cost.

1. **§A.51(b) — the gates cap is PER VALUE and defaults to `EXTERNALISE_ABOVE_BYTES`.** 64 KiB,
   deliberately the same number the journal already uses rather than a second one nobody chose.
   Over it, the value is replaced in place by `{"$truncated":{bytes,shown,head}}` — a marker rather
   than a silent cut, because a value silently truncated is a value an operator reads as complete
   and this door's whole subject is a human deciding on what it shows. `--max-bytes N` raises it,
   `--max-bytes 0` lifts it, and 1 GiB is the ceiling, because `Number.isInteger(1e30)` is `true`
   and a mistyped exponent would print everything while truncating nothing and therefore saying
   nothing. **The alternative not taken** was a per-OUTPUT budget, which is what §A.51(b)'s worst
   case (one gate per fan-out branch) actually describes; it is residue in §A.58(2).
2. **§A.49 — the refusal reads OBSERVED raise classes, not `errors.ts`'s section comments.** The
   row's premise was partly false: class is chosen at the raise site, NINE codes are raised under
   more than one class (the table's own count; the test's header still says ten, from the scan
   that produced it), and five section comments disagree with their own raise sites about
   retryability. A table built from the comments would have refused two codes that WORK and let
   three through that cannot. `RAISED_CLASS` is a `Record<Code, readonly ErrorClass[]>`, so its
   drift guard is `tsc` rather than a grep. **An empty class set ACCEPTS** — refusing on a class
   nothing pins would be the same false refusal the comment table was rejected for.
3. **§A.53 — the remedy became ADDITIVE, and that is what ended four fix rounds.** Rounds 1-3 each
   reopened one edge over: a membership test that dictated graphs which then broke, a barrier
   picked by reachability so the message named a join it could not know, and a `fix:` that
   REPLACED a join's `branches` instead of adding to them. That accretion of special cases in one
   predicate is the documented tell that a fix is mis-scoped rather than incomplete. The final form
   stops narrowing: it names the joins it OFFERS, and the multi-candidate arm filters `waitsFor` to
   the ancestors of every candidate in BOTH arms.
4. **§H.9 — the floor is 3,500+, not the true number.** A floor's whole value is that growth costs
   no doc edit, so it is set well below the measurement (3,586 at the time) and the `claims` string
   is anchored on `+ tests` so the digits can move without a second edit.
5. **§A.46 — `checkpoint.restored{mode:"fork"}` is deliberately NOT handled.** A fork suppresses
   nothing in the run being watched, so the console's fold has nothing to undo. It is written at
   the arm rather than left to be rediscovered.

## 5 · Facts you would otherwise rediscover

- **The three tests that fail in a fresh worktree are an artifact of the worktree, not a defect.**
  `guards-lane-surface-guard-decides` and the two `toolchain-gate` suites want `dist/` and
  `node_modules`, which a worktree does not have. In the main checkout, after `npm run check`
  builds, all three pass. Do not chase them from a lane.
- **`security/redact-channels.ts` is intentionally not exported from `index.ts`.** The surface
  guard's 542 is unchanged BECAUSE of that choice, not in spite of it: a redaction rule two in-tree
  callers share is not something a stranger needs to import, and exporting it would pin it.
- **`#fireEmptyJoin` must not be routed through `#maybeFireJoin`.** §A.47's row predicted this and
  the build confirmed it: the planner's `take` still holds the `fanout` edge whose `to` is a
  declared member, so `handingOff` stays true and `quiescent` never becomes true — the empty fan
  strands instead of releasing. An empty fan needs `#maybeFireJoin` to be TOLD the fan planned zero
  branches. It is not a call-site swap.
- **W6 was kept, and deleting it is still wrong.** The tempting corollary — the engine routes
  correctly now, so the compile-time clause is redundant — would re-key a compile-time guard on
  WHICH ENGINE METHODS TEST QUIESCENCE, the enumeration shape defeated three times before
  `ac693d0`. Whether to ADD a rule is §D.8; whether to remove one is settled.
- **The `A.50` fix changed which side an existing example test sits on, and RENAMED it.**
  `test/examples-triage.test.ts:495` was "a fan-out width that is not a NUMBER is unreadable, not
  skipped" and is now "…is refused BY THE COMPILER, before any body runs": the case no longer
  reaches the userland body. Grepping the old string finds nothing — that is the rename, not a
  deletion.
- **`GATE_READ_SWEEP` is `Number.POSITIVE_INFINITY` on the `loom gates` door** and finite on
  `loom serve`, on purpose: `gates` is a one-shot a human is reading and is about to render the
  value anyway; `serve` sweeps every frame of a live stream.
- **The A.53 reviewer's evidence is differential and reproducible in shape, not in file.** An
  8,000-graph sweep against `c98a108` loosened 0; of 31,442 graphs reproducing F1 (26,827 with a
  `seq`-wired inner join) all converge in one step over 65,126 choice combinations; 29,748
  reachable-but-not-offered joins each break the graph if dictated. The harnesses lived in the
  lanes' gitignored `.agent/` directories and are gone with them — the durable pins are
  `test/graph/fanout-branch-diagnostic.test.ts`'s 14 assertions, which parse the message's name
  sets and THROW on a sentence they do not recognise.
- **A CLOSURE FALSIFIES PROSE THAT CITES THE DEFECT, and the settlement nearly missed one.**
  `examples/README.md` §8 taught the two-compile fan-out rule as a fact ("Two compiles to find,
  and the second diagnostic is the one that says what to do") — true until `51f4a5f`, false after,
  and the only breadcrumb to it was the F1 status line the settlement itself overwrote. A fresh
  reviewer found it. **When a row closes, grep the tree for the BEHAVIOUR the row described, not
  just for the row id**: `examples/README.md`, `README.md` and the `docs/` records each teach
  behaviour and none of them cites a TODO id.
- **A builder's own green suite is still not evidence.** Every lane in this wave shipped green and

  a help text promising a cap the code does not apply (`b96d887`), the OTHER operand of the very
