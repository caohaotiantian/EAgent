## 1. Background and Purpose

EAgent already has two extensions that persist what happened in a run, and
neither produces something you can *resume from*:

- `memory` (`src/extensions/memory.ts`) stores unstructured key/value notes plus
  a scratchpad. It is a lossy bag of facts; it does not capture the shape of the
  work (what's done, what's pending, what not to touch).
- `journal` (`src/extensions/journal.ts`) is an append-only JSONL log of every
  `message` (journal.ts:43, `e.on("message", …)`). `/resume` replays the *raw*
  transcript verbatim — to pick up work in a fresh thread you re-read the whole
  log, paying the full transcript cost again.

The convergent production pattern (Claude Code's handoff/"compact-and-continue",
Cursor's session summaries) is different: on session end, **distill** the
transcript into a *fixed schema* — goal; completed / in-progress / pending;
files touched; commands run; open decisions; do-not-touch; next 3–7 steps —
plus a paste-ready **reactivation** prompt, and write it to a gitignored file.
Resuming then costs *a summary*, not the raw log.

`compact` (`src/extensions/compact.ts`) summarizes too, but *within a run* to
relieve context pressure (it folds the older prefix on the `transformContext`
seam, compact.ts:244). It never crosses a session boundary and never emits a
resume artifact.

This document specifies a **new `handoff` extension**: a `/handoff` command and
an `agent_end` observer that summarize the transcript via a recursion-safe,
tool-less provider sub-call (the `risk-guard`/`compact` pattern) into the fixed
handoff schema, write it to a gitignored `.eagent/handoffs/<date>-<slug>.md`,
and emit a short reactivation paragraph. Off by default (it makes a model call).

## 3. Scope Boundary (NON-goals — Simplicity First)

1. **No automatic session-start resume injection.** The extension does **not**
   read a prior handoff and inject it into a fresh run's context (see D5). A
   stale handoff dropped into an unrelated task is the dominant risk, and getting
   relevance-gating right is its own design. Resuming is *manual*: the user pastes
   the reactivation paragraph (or `cat`s the file). Deferred, not built.
2. **No relevance/similarity matching.** No embeddings, no "latest matching"
   selection, no per-project index. Out of scope for the same reason as (1).
3. **No new capability and no filesystem capability declaration.** The only
   privileged action is the provider sub-call, which rides the agent's existing
   provider exactly as `risk-guard`/`compact` do. Writing under `.eagent/`
   mirrors the `limits` spill writer (limits.ts:169-181), which also writes there
   with no capability.
4. **No transcript mutation.** Unlike `compact` (which rewrites `transformContext`)
   `handoff` only *reads* `e.agent.messages` and *writes a file*. It never steers,
   follows up, prunes, or edits the live transcript.
5. **No retention sweep / rotation.** Handoff files are small and human-owned;
   the `limits` retention sweep (limits.ts:332) is for machine-generated spill
   and is not replicated here. (May be added later if files pile up.)
6. **No multi-format output** (no JSON, no HTML). One Markdown file, one schema.
7. **No "resume" command, no journal-replay integration.** That is `journal`'s
   `/resume`. `handoff` produces an artifact; it does not consume one.

## 4. Key Design Decisions

### D1 — Trigger: auto on `agent_end` **and** manual `/handoff`

- **Problem.** When should a handoff be produced? At natural end of work, or only
  when the user remembers to ask?
- **Options.** (a) `agent_end` observer only; (b) `/handoff` command only;
  (c) both.
- **Choice: both** — an `e.on("agent_end", …)` observer (auto) *and* a
  `/handoff` command (manual). `agent_end` fires in the agent loop's `finally`
  with `{ reason }` (agent.ts:235, events.ts:20); at that point the full
  transcript is readable via `e.agent.messages` (agent.ts:98-100, exposed on the
  ExtensionAPI as `e.agent`, extension.ts:60). The observer only acts when
  *enabled* (off by default, D6); `/handoff` works regardless of the enabled flag
  so a user can snapshot on demand.
- **Why not (a) only.** A user mid-session, before the loop idles, can't snapshot
  the current state — the most common "I'm switching threads now" moment.
- **Why not (b) only.** The whole value is *not having to remember*. The convergent
  pattern auto-distills at session end; making it purely manual reproduces
  `memory`'s "you must remember to write it down" failure mode.

### D2 — Summarizer: recursion-safe tool-less provider sub-call (not a subagent)

- **Problem.** How to turn the transcript into the schema?
- **Options.** (a) A tool-less `provider.stream({ …, tools: [] })` sub-call;
  (b) a `subagents` sub-agent run; (c) a deterministic provider-free template
  that just stitches message text.
- **Choice: (a)**, copied verbatim in shape from `risk-guard.ts:96-137` and
  `compact.ts:184-202`: get `e.agent.providers.get()`, stream with
  `systemPrompt` = the schema instruction, `messages` = the transcript,
  `tools: []`, `model: e.agent.model`, read the `done` event's text. Passing
  `tools: []` means the completion *cannot emit a tool call* and therefore cannot
  re-enter any hook seam — the structural recursion guard. A boolean re-entrancy
  flag (`summarizing`, mirroring compact.ts:175,245) additionally prevents an
  `agent_end` fired during the sub-call from recursing. The sub-call **fails
  open / fails soft**: no provider, a throw, or an empty reply degrades to a
  deterministic provider-free digest (compact.ts:129-150 pattern) so a handoff is
  still written.
- **Why not (b) subagents.** A sub-agent gets its own loop, tools, and turns —
  more expensive, and it *can* recurse (its own `agent_end` would re-fire the
  observer). The tool-less sub-call is strictly cheaper and structurally
  recursion-proof. This is exactly why `compact` and `risk-guard` both chose the
  sub-call over a sub-agent.
- **Why not (c) template-only.** A pure stitch is what `journal` already gives
  (the raw log) — it doesn't *distill*. We keep the template only as the
  fail-open fallback, not the primary path.

### D3 — Fixed handoff schema (not free-form)

- **Problem.** What structure does the summary take?
- **Options.** (a) A fixed schema with named sections; (b) free-form prose.
- **Choice: (a)** — a fixed Markdown schema with exactly these sections:
  `## Goal`, `## Completed`, `## In progress`, `## Pending`, `## Files touched`,
  `## Commands run`, `## Open decisions`, `## Do not touch`, `## Next steps`
  (3–7 items), followed by a `## Reactivation` paste-ready paragraph. The section
  set is encoded once in the system prompt (a string constant, like
  `COMPACT_SYSTEM_PROMPT`, compact.ts:51-58) and asserted by the tests.
- **Why not (b) free-form.** Free-form is precisely `memory`'s lossy approach —
  the model silently drops the active plan or the do-not-touch list. A fixed
  schema *is the point*: a resumer scans named sections instead of re-reading
  prose. (The specific section names/order are a string/format choice and
  self-justify as non-behavioral; the fixed-vs-free decision is the behavioral one.)

### D4 — Write location: `.eagent/handoffs/<date>-<slug>.md` (gitignored)

- **Problem.** Where does the artifact go, and how is the filename derived?
- **Options for the directory.** (a) `.eagent/handoffs/` under the workspace
  root (gitignored); (b) `~/.eagent/` (user-global); (c) the workspace root
  itself (committed).
- **Choice: (a)** — reuse the `limits` convention exactly: workspace root via
  `EAGENT_WORKSPACE` else `process.cwd()` (limits.ts:58-60), then
  `join(root, ".eagent", "handoffs")`, `mkdirSync(…, { recursive: true })`
  (limits.ts:171-172). `.eagent/` is already gitignored (`.gitignore:4`), so the
  artifact never pollutes a commit.
- **Why not (b).** A handoff is *about this project's work*; co-locating it with
  the project (and honoring `EAGENT_WORKSPACE`, the offline-test seam recovery.ts
  uses) keeps it discoverable and per-project. User-global mixes projects.
- **Why not (c).** Committing a machine-generated resume doc is noise in version
  control; gitignored under `.eagent/` is the established EAgent convention.
- **Slug derivation.** `<date>` is `YYYY-MM-DD`; `<slug>` is a kebab-cased,
  lowercased, ASCII-only, length-capped (e.g. ≤ 40 chars) excerpt of the **first
  user message** in `e.agent.messages` (the run's goal), with non-`[a-z0-9]`
  runs collapsed to `-`. Empty/whitespace first message → slug `session`.
  **Collision handling:** the same `Date.now()`-class concern noted in
  limits.ts:143 (two writes in the same ms) — two handoffs with the same date+slug
  must not clobber. Mitigation: append a monotonic suffix when the target path
  already exists (`<date>-<slug>.md`, then `<date>-<slug>-2.md`, …) using
  `existsSync`; this is deterministic and offline-testable (no reliance on
  sub-millisecond timestamps). The date is derived from a single `new Date()` read;
  tests may pin it by passing an injected `now`/`date` (kept internal, default
  `new Date()`), so assertions don't race the clock.

### D5 — Session-start resume injection: **defer** (do not build now)

- **Problem.** Should `handoff` also *inject* the latest handoff into a fresh
  session via `transformContext` so resume is automatic?
- **Options.** (a) Defer entirely (Scope Boundary §3.1); (b) inject the *single
  latest* handoff file unconditionally; (c) inject the *relevance-matched* handoff.
- **Choice: (a) defer.** Build only the *write* side now.
- **Why not (c).** Relevance-gating (matching a stored handoff to the new task)
  is the genuinely hard, risky part — a wrong match injects stale, misleading
  context into an unrelated task and silently steers the model. That deserves its
  own design, not a corner of this one.
- **Why not (b) inject-latest-unconditionally.** "Latest" is almost never "the one
  this new task is about". Injecting the last project's handoff into a different
  task is the same staleness failure as (c) with worse precision. The safe default
  is *no* injection; the user pastes the `## Reactivation` paragraph when (and only
  when) it's the right one. This keeps the extension single-purpose and Simplicity-First.

### D6 — Posture: off by default + `EAGENT_HANDOFF=off`

- **Problem.** Should the `agent_end` observer run for everyone?
- **Options.** (a) On by default; (b) off by default with an explicit enable.
- **Choice: (b)** — the auto-trigger is **off by default** and enabled via
  `/handoff on` (persisted in `e.store`, mirroring risk-guard.ts:81 and
  compact.ts:168-169), with a hard env kill `EAGENT_HANDOFF=off` read inside the
  trigger. The manual `/handoff` command always works regardless.
- **Why not (a) on by default.** The observer makes a **paid, latency-adding model
  call on every session end** — the exact reason `risk-guard` (risk-guard.ts:18)
  and `compact` (compact.ts:26) ship off. A guard/feature that adds an unasked-for
  round-trip must be opt-in. The two-tier posture (auto opt-in; manual always
  available) matches `risk-guard`'s `enabled` flag + always-present `/risk-guard`
  command.

## 5. Dependencies and Assumptions

- **Kernel surfaces (verified):**
  - `e.on("agent_end", …)` with payload `{ reason: StopReason }` (events.ts:20),
    emitted in the loop's `finally` (agent.ts:235).
  - `e.agent.messages` — the live transcript, a `readonly Message[]`
    (agent.ts:98-100), reachable via the `e.agent` field on the ExtensionAPI
    (extension.ts:60).
  - `e.agent.providers.get()`, `e.agent.model` — the same provider/model handles
    `risk-guard` (risk-guard.ts:98,128) and `compact` (compact.ts:186,193) use for
    the tool-less sub-call.
  - `provider.stream({ systemPrompt, messages, tools: [], model, signal })`
    yielding a `done` event whose `.message` text is the summary (risk-guard.ts:124-132).
  - `e.registerCommand`, `e.store.get/set`, `e.log` (extension.ts:43-60).
- **Standard library only:** `node:fs` (`mkdirSync`, `writeFileSync`,
  `existsSync`) and `node:path` (`join`, `resolve`), exactly as `limits` uses
  (limits.ts:20-21). **Zero new npm dependencies** (house rule).
- **House rules:** ESM with `.js` import specifiers even for `.ts`; strict TS
  (`noUncheckedIndexedAccess`, no `any`); `text()` helper imported from
  `../kernel/types.js` (types.ts:87) if a `Message` is constructed.
- **Assumptions:**
  - The transcript at `agent_end` is non-trivial often enough to be worth
    summarizing; an empty/near-empty transcript writes a minimal handoff
    (still schema-valid) — no special-casing beyond a non-empty fallback digest.
  - `MockProvider` can be scripted to return a schema-shaped summary for the
    sub-call (mock.ts:33-61), keeping the suite offline. The sub-call is the
    *next* `stream` after the run's turns; tests use a responder *function*
    (mock.ts:36) that branches on the handoff system prompt (the prompt contains
    a distinctive word, the `compact.ts:46-48` "must contain a recognizable token"
    convention) to serve the summary deterministically.
  - Writing under the workspace `.eagent/` is permitted (the dir is gitignored
    and `limits` already writes there).

## 6. Relationship with Existing Designs

This is **not a first-of-its-kind** extension; it composes three established
patterns and dedups against two siblings.

- **`risk-guard` (`src/extensions/risk-guard.ts`)** — the closest *mechanism*.
  Its `classify()` (risk-guard.ts:96-137) is the recursion-safe, tool-less
  provider sub-call to copy: `tools: []`, `model: e.agent.model`, read the `done`
  text, fail open on any error. `handoff` reuses this shape for `summarize()`.
- **`compact` (`src/extensions/compact.ts`)** — the closest *summarizer*. Same
  tool-less sub-call (compact.ts:184-202), same fixed-section system prompt idea
  (compact.ts:51-58), same fail-open-to-deterministic-digest fallback
  (compact.ts:129-150). **Dedup / conflict: none.** `compact` distills *within a
  run* on `transformContext` to relieve context pressure and *rewrites the live
  context*; `handoff` distills *across sessions* on `agent_end`, *writes a file*,
  and never touches the transcript. Distinct trigger (transformContext vs
  agent_end), distinct consumer (the model's next turn vs a human/fresh thread).
- **`limits` (`src/extensions/limits.ts`)** — the closest *file-writing*
  convention. `.eagent/<subdir>/` under the workspace root, `mkdirSync` recursive,
  defensive disk writes, no capability (limits.ts:169-181). `handoff` reuses the
  `.eagent/` gitignored-spill convention (subdir `handoffs/`).
- **`memory` (`src/extensions/memory.ts`)** — raw *facts* this distills. Dedup:
  `memory` stores unstructured k/v + scratchpad with no fixed shape; `handoff`
  produces a fixed-schema resume artifact. Different shape, different lifecycle.
- **`journal` (`src/extensions/journal.ts`)** — raw *events* this distills.
  Dedup: `journal` appends every `message` to JSONL and `/resume` replays the raw
  log; `handoff` writes one distilled, paste-ready document. Resuming from
  `journal` costs the raw transcript; resuming from `handoff` costs a summary.

No conflicting hook ownership: `handoff` registers an `agent_end` *observer*
(read-only) and a command; it claims no filter seam that another extension owns.

## 7. Acceptance Criteria (measurable / automatable)

All via `makeHarness` (`test/helpers.ts`), offline, loaded with
`host.use("handoff", handoff)` (the `recovery.test.ts` pattern), writing into a
temp workspace via `EAGENT_WORKSPACE` (recovery.test.ts:88-89). Each is a runnable
assertion.

- **AC-1 (sub-call served by mock).** With a responder that branches on the
  handoff system prompt and returns a schema-shaped summary, running `/handoff`
  produces a file whose contents include that mock summary text. Assert
  `existsSync(path) === true` and the file content `.includes(<mock summary
  marker>)`.
- **AC-2 (schema sections present).** The written file contains every required
  section header. Assert `/## Goal/`, `/## Completed/`, `/## In progress/`,
  `/## Pending/`, `/## Files touched/`, `/## Commands run/`, `/## Open decisions/`,
  `/## Do not touch/`, `/## Next steps/` all `.test(content)`.
- **AC-3 (reactivation paragraph).** The file contains a `## Reactivation`
  section with non-empty body text. Assert `/## Reactivation/.test(content)` and
  the captured body length `> 0`.
- **AC-4 (`/handoff` works on demand).** Invoking the command (even with the
  auto-trigger off) writes exactly one handoff file under
  `<workspace>/.eagent/handoffs/` matching `^\d{4}-\d{2}-\d{2}-.+\.md$`. Assert
  `readdirSync(dir).length === 1` and the name matches.
- **AC-5 (auto-trigger fires when enabled).** With `/handoff on` (or
  `store.set("enabled", true)`), after `agent.run(...)` completes, a handoff file
  exists. Assert the directory is non-empty after the run.
- **AC-6 (off by default).** With a fresh harness and *no* enable, after
  `agent.run(...)` the handoffs directory is absent or empty. Assert
  `!existsSync(dir) || readdirSync(dir).length === 0`.
- **AC-7 (kill switch).** With `EAGENT_HANDOFF=off` and the enabled flag *on*,
  after `agent.run(...)` no handoff file is written. Assert directory empty;
  restore the env var in `finally` (recovery.test.ts:149-171 pattern).
- **AC-8 (fail-open / no provider).** With the provider removed (or a sub-call
  that throws), `/handoff` still writes a schema-valid file (the deterministic
  digest fallback). Assert `existsSync(path)` and AC-2's section headers still
  present.
- **AC-9 (slug from first user message; collision-safe).** Two `/handoff`
  invocations in the same session/day produce two distinct files (e.g.
  `…-<slug>.md` and `…-<slug>-2.md`). Assert `readdirSync(dir).length === 2` and
  the two names differ.
- **AC-10 (clean dispose).** After `host.unload("handoff")`, a subsequent
  `agent.run(...)` with the flag previously on writes **no** new handoff (the
  `agent_end` observer is gone). Assert the post-unload directory count is
  unchanged (recovery.test.ts:173-192 pattern). Dispose must not throw.

## 8. Risks and Rollback

- **R1 — extra model call on session end.** The `agent_end` summarization is a
  paid, latency-adding round-trip. *Mitigations:* off by default (D6); the manual
  `/handoff` is the only always-on path; the suite scripts `MockProvider` so it's
  fully offline-testable (AC-1/AC-5).
- **R2 — stale resume injected into an unrelated task.** *Mitigation:* there is
  **no** auto-injection — D5/§3.1 defer it. The artifact is inert until a human
  pastes the `## Reactivation` paragraph, so a stale handoff cannot silently steer
  a new task.
- **R3 — writing under `.eagent/` leaking into git.** *Mitigation:* `.eagent/` is
  already gitignored (`.gitignore:4`); verified at closeout. The writer is
  defensive (try/catch around all disk ops, like limits.ts:169-185) so a disk
  failure logs a warning and never crashes the run.
- **R4 — filename collisions / clock races.** *Mitigation:* `existsSync`-guarded
  monotonic suffix (D4), not sub-millisecond timestamps; the injected `now` seam
  makes date assertions deterministic offline.
- **R5 — empty/degenerate transcript.** *Mitigation:* the fail-open digest
  (D2/AC-8) guarantees a non-empty, schema-valid file even with no provider and a
  near-empty transcript.

**Rollback.** Set `EAGENT_HANDOFF=off` (hard kill of the auto-trigger;
`/handoff` still available manually) or `host.unload("handoff")` /
`/unload handoff` to remove the extension entirely. The dispose loop tears down
the `agent_end` observer and the command and never throws (AC-10). Because the
extension only *reads* the transcript and *writes a gitignored file*, removing it
leaves no residue in the live agent state — only the already-written, gitignored
handoff files remain on disk, harmlessly.
