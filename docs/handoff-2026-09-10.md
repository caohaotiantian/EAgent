## 3 · Decisions taken without the user this wave, still in force

- **A REFUSAL IS A RETURN, NOT A THROW, and that was forced rather than chosen.** `isLoomError` is
  an `instanceof` against the host class and `toLoomError` deliberately refuses to read a `class`
  off injected code, so a guest object can never BE a host error — the raise has to happen inside
  the executor. That makes the body's vocabulary `OUTCOME_KEYS`, a closed literal in `run/engine.ts`
  read by `requireOutcome`, the one validator both callers share. `{refuse: {reason}}` is therefore
  the second member of the same shape `{retry: {reason}}` already had, and the two are written to
  share every rule and differ only in meaning.
- **`E_FUNCTION_REFUSED` is class `validation`, and the alternatives were rejected for reasons worth
  keeping.** `internal` was the status quo and is what the row existed to leave. A new class was
  refused because `ErrorClass` is read by `RETRYABLE`, by the audit rules and by every
  `retry.onlyIf`, and adding one makes every existing consumer's exhaustiveness claim false.
  `policy` — the class that means "denied by policy", and the one an earlier
  draft of this miscalled `permission`, a class this taxonomy does not have — was refused because a
  body refusing its own inputs is not an authorization event.
  `validation` gets it right by construction: it is not in `RETRYABLE`, so `#retryDecision` returns
  before it consults any policy, which is what "a second attempt with the same inputs will not
  work either" means operationally rather than only in prose.
- **`ctx.node` carries `{id, type, reads, writes, out}` and deliberately NOT `timeoutMs`.** The
  membership rule is *what the GRAPH declares about this node*, and `timeoutMs` fails it in the one
  way that matters: it is not the bound the body is actually running under, because
  `resources/functions.ts`'s `REBIND_DEADLINE` recompiles the realm at another number through a
  `Symbol.for` back-channel. Publishing it would have handed a body a figure it could not act on,
  which is the defect §A.44 was about, one level up. `out` carries the fan-out shape
  (`{id, kind, over?, as?, maxWidth?, maxIterations?}`) because that is what the port actually
  needed.
- **§A.43's `reads` is swept by the graph's own classification, and the first version was not.** It
  shipped in the clear on the argument that `loom run` and `loom approve` already print
  `p.outputs` — but `outputs` is an author-chosen PUBLISHED subset while this is
  `observedChannels`, which includes INPUTS, so it would have been the first CLI path to print a
  channel a graph declared `secret_ref`, at the gate the classification exists to protect. A
  reviewer caught it, the lane's history was rebuilt, and no commit on `loom` ever printed one. It
  costs §A.43 nothing: an undeclared classification is `internal` and prose passes through whole.
  It is NOT truncated, and that half is §A.51.
- **§A.41's hint moved to stderr and NOT to both streams.** Duplicating it would make the stdout
  contract "JSON plus whatever we also felt like saying", which is the thing that broke; the run-id
  hint had already settled the rule and the gate hint was the one line not obeying it.
- **W6 is keyed on the join's INBOUND EDGE LIST, and that is the whole design.** Three builder-side
  review rounds each found one more entrance to the barrier and each patched the enumeration; a
  fresh agent told to REFUTE broke the third with a running repro — a plain `seq` edge into the join
  mints the task through `#activate` with no quiescence test, and branch b read branch d's value on
  the shipped example's own shape. The fix was to stop enumerating engine methods, which the
  validator cannot see and nothing keeps in step, and require instead *exactly one `kind:"join"`
  edge per declared member and nothing else* — a property of the GRAPH. **The round cap was raised
  to four deliberately**, on the argument that each round was finding a NEW entrance rather than
  reopening one edge over; the fourth round is the one that changed the key rather than adding a
  case, and a fifth reviewer then failed to break it — `dc73059`'s body records
  2,188 driven perturbations across two sweeps, 660 exempted-and-run, 273 on the fall-through path
  every leak so far has used, zero cross-branch reads. What it found instead was three places where
  the PROSE claimed more than the code did, which is `dc73059`.
- **W2 was NOT widened to dominance, and that is a deferral, not an oversight.**
  `fan.to === writer` stands in for "the writer dominates every reader", which is only sound because
  the two coincide at the fan-out's own target. Widening it needs a real dominance computation, and
  *"refusing is always allowed; loosening never is"* means it needs its own adversarial review
  rather than riding on this one. §A.48(a) is the row.
- **The examples lane takes the TIGHTEST `maxWidth` over all matching fan-outs**, not the first and
  not the widest. A node may carry several `fanout` edges over the same channel; the body's job is
  to refuse before shards are dropped, and only the narrowest edge bounds that. It also refuses
  rather than proceeding when the listing carries `fs.glob`'s truncation marker — the marker means
  "there were more", and a plan built on a silently short list is the same defect the ceiling
  refusal exists to prevent.
- **A source-text drift check was replaced by a behaviour drive, after a reviewer defeated it.** The
  first version read `triage-plan.js` as TEXT and required the shipped width not to appear plus a
  `/ctx\.node/` match; `const CEILING = 0x18; const _unused = ctx.node;` passes every assertion and
  hard-codes 24. The replacement edits `fan.maxWidth` to 3 in a throwaway workspace and requires the
  refusal to NAME 3 and not 24. That is the general lesson: **a source-text check can ask whether a
  spelling is absent, never what the body does.**
- **Two of this settlement's own instructed edits were REVERTED because the repository refused
  them, and the refusals were right.** The instruction was to replace README's `2,300+ tests` with
  the re-run number and to rename the `retry` gaps row. `readme-gaps.test.ts` failed four
  assertions on both. Re-reading the guard settled it: the Gates row is deliberately a FLOOR
  (`N+ tests`, checked against the suite's actual count) because a bare number is exactly the drift
  `TODO.md`'s rule 3 warns about, and the gaps probes bind to `claims` SUBSTRINGS rather than to row
  names. Both phrases were restored verbatim and the new content written around them; the whole
  verdict story is in the row and the row still carries the probed sentence. **The residue became
  §H.9**: the same entry's `claims` string pins the digits, so the floor cannot be raised at all
  without a test edit, and 2,300 is now 38% below the truth. A docs pass may not edit the test that
  pins the doc, which is why it is a row.
