## 3 · The one that was bigger than it looked

Lane P's register row was *"the gates queue refolds every journal per poll"* — a perf row, half
already paid by `d9a24f9`. Lane P paid the gateless half (`#endedAtHead`, one indexed row per
finished run) and deferred the open-gate half to the gates lane with a named fix: *let `list` take
the projection the handler already holds*. The gates lane did not do that; it made
`HumanGateBroker.project` incremental instead, keeping a `RunFolder` per run, which fixed
`resolve`, `raise`, `claim`, `sweepTimeouts` and every `openGates` caller at once without touching
`engine.ts`.

That is where the size was. A per-process fold cache is state a restart empties — safe, an empty
map folds from seq 1 as every caller always did — but it is also state keyed by something, and the
only handle a `RunLog` offers is `runId`. The first reviewer reproduced one broker over two stores
holding one run id: `project` on store two's EMPTY journal returned store one's whole projection,
`awaiting_gate` and gate included, silently. Round one (`00232f7`) added a mark — the `(seq, ts,
type)` of the last folded event — re-read from `lastSeq` and refused on disagreement. The lane then
wrote a docstring saying the residual needs two *byte-identical* events (`34da51a`). The second
reviewer refuted the docstring, not the fix: three matching fields suffice however far the payloads
diverge, and its reproduction (`run.suspended{reason:"operator"}` vs `{reason:"gate"}` at the mark)
folds to `awaiting_gate` where the cold fold gives `interrupted`. Round two (`6b23621`) restated the
bound as measured and pinned the reviewer's input as a test named *the mark is payload-blind*, so
strengthening `describes` moves a test rather than passing silently.

The residual is not fixed and says why: `Engine` builds its own broker, `cli.ts` one per process,
`replayRun` deletes `gates` from the options it forwards — reaching it needs one ULID minted into
two stores on purpose. Both reviewers classed it major, not blocking. **The transferable part:** a
`perf:` commit added a process-local cache, and the two questions that found its defects were the
two CLAUDE.md names — *what does it do when a restart hands it back empty* (fine) and *what is the
key, and can two things share it* (not fine). Neither reviewer reproduced the HTTP-level counts;
the lane measured those itself with the audit's own probe, twice, and says so.

## 9 · Facts you would otherwise rediscover

- **`node_modules` is a symlink and `.gitignore` said `node_modules/`**, which does not match a
  symlink; `git add -A` staged it. Fixed at `b8c55c8` (`node_modules`, no slash) — but the six
  wave-2 worktrees branched before it and still show `?? node_modules`.
- **`git merge` run from inside a worktree merges into THAT worktree's branch**, not into `loom`.
  The orchestrator reports it happened once and was undone; `loom`'s reflog shows only the seven
  intended merges. Run merges from the main checkout.
- **The single-file binary is transiently unrunnable during a concurrent rebuild**: lane P
  measured `./bin/loom --help` exiting 137 with no output while the file was being written, and
  0 on three retries six seconds later. Scripts should treat 137-with-empty-output as retry, and
  the freshness stamp cannot cover a half-written file.
- **`npm test`'s count is not the number of tests that ran.** Reproduced today: a file of four
  tests whose bodies only replace `process.stdout.write` reports `ℹ tests 1 / pass 1`. And
  `node --test packages/core/test/cli/cli.test.ts` reports `tests 38 / pass 38` on `8d43127` —
  both are true; the 2026-09-02 correction was about a file that restores stdout, lane P's about
  one that does not. A failing test in a hijacking file exits 1 naming only the FILE. Lane P's new
  suites drive the CLI in a child process for this reason.
- **Rate-limit cutoffs kill background reviewers silently.** Lane P's reviewer was cut off twice
  before completing on a third attempt; the gates lane's first reviewer was cut off after
  reporting; the orchestrator's account is that every lane was resumed from its transcript at
  least once. Resume and re-spawn reviewers synchronously, and expect a lane's final message to
  be lost — the report file is what survives.
- **`.agent/` in a worktree is deleted by `git worktree remove`.** Copied today to
  `.agent/wave-2026-09-05/lanes/<lane>/` (36 files, 11 lanes) before writing this.
- **macOS zsh has no `timeout`**; `timeout 60 …` produces empty output that reads as a hang
  (gates lane).
- `git archive <sha> | tar -x -C <dir>` is still the cheap base-proof, but one extraction per
  lane — the shared `base/` directory was used by two lanes at once.
- A `function` body written `({ amount }) => …` destructures a property that does not exist and
  writes a plausible wrong number silently; the API is `view.require("amount")`, which fails
  loudly (lane P, on its own fixture).
- `check-surface.mjs` reads `dist/`: a tree with NO `dist/` fails it (`scripts/check-surface.mjs:44-47`
  exits 1 naming `npm run build`), and a tree with a STALE `dist/` passes it. The 2026-09-03
