### §A.73 — ten arms, not six, and the count is the mechanism

The row asked for one thing: that following any one `fix:` line of a compile does not contradict
another line of the SAME compile. Two shapes were wrong. On `eto-noedge`, GRAPH021's tail said
"whatever edge runs there now carries its own meaning" where **nothing runs there**; on `eto` with
its `loop` edge, `rule008`'s `JOIN_DEPTH` dictated dropping "the `kind: join` edge from \"read\""
where the only edge is a `loop`. Both now read the graph in hand, and the second names the kind that
IS there.

**`GRAPH008_BRANCH_NOT_CONNECTED` was left alone, on a measurement rather than on taste.** Following
its line alone — add `read --join--> again` — compiles CLEAN in one compile (`ok`, exit 0, re-run by
this settlement). It is the cheapest correct edit, so teaching it to defer would be teaching it to
hedge about the better instruction. The row offered that closure and it was refused.

**The arm count is the part that generalises.** 2026-09-18's §5 said *a byte pin covers exactly ONE
arm of a conditional string; count the arms first* — and the lane's design counted six. The real
number is **ten**, and it is only knowable by enumerating them BY CONSTRUCTION: `ARMS` in
`fanout-branch-diagnostic.test.ts` (O1, S1–S3, P1–P6), each byte-pinned, **plus a test that the ten
strings are DISTINCT** — two arms pinning one string would mean a condition is inert — **and that
the counterfactual appears exactly where no claimer cycles**. §A.69's two settled strings are among
the ten, unchanged and still byte-identical to 2026-09-15b's quotation.

**The blocking finding was an injection, and its enabling condition is worth carrying.**

**The NOTE is three shapes, not one, and they are handled in one place.** The row carried the

### §H.14 — wrap for a terminal, never for a pipe, and the pipe claim needed a real pipe

`process.stderr.columns`, read only when `process.stderr.isTTY === true`, clamped `[60, 120]`; a TTY
with no `columns` does NOT wrap. **`COLUMNS` is deliberately unread** — honouring it would make the
bytes a diagnostic writes depend on the invoking shell even in a pipe, which is exactly the grep cost
the row named, reintroduced through a side door. `wrapDiagnostic` breaks at whitespace only (the
longest token is 21 characters, so nothing splits at any width ≥ 60), treats a `"…"` or `` `…` `` span
as one token, and **preserves every gap it does not break at** — the first cut joined with one space
and turned `bad  name.json` into `bad name.json`, a path that does not exist.

**The blocking finding is the lesson: a "pipe" test must be a pipe.** The in-process capture set
`isTTY` to the literal `false`. A real pipe has **no own `isTTY` property at all** — so the pipe arm
was asserting a state that never occurs, and two mutations (always wrap; wrap at 80 when
`isTTY === undefined`) were GREEN across the whole suite. `loom compile 2>&1 | grep` returning
nothing could have shipped under a green gate. It is now driven by `execFile` on the real binary.

**Two residues, recorded rather than closed.** `loom compile 2>&1 | less` is a pipe and gets the
852-byte line; a pty-allocating CI runner is a TTY and gets a wrap — no rule distinguishes `less`
from `grep` at the file descriptor. And the TTY path strips `SPOOFING_BUT_WHITESPACE` (the class
`legible()` already used, spelled once and read by both) because `loadGraph` interpolates a FILE NAME
unquoted, so **on a terminal the rendered file name is not the file name**: `a<CR>b.json` renders
`a b.json`. That is the same defect whitespace-collapsing caused, paid deliberately, because any
faithful rendering of a CR on a terminal IS the attack. The pipe is unchanged and a test asserts that
residue, so nobody reads the TTY arm as having closed it.

**The clause was not shortened**, per the row's instruction — 852 bytes on `eto`, byte-identical to
2026-09-15b's quotation. §A.73's new arms made the OTHER arms longer, and this settlement measured
all of them: the unwired offer **889** (852 at base), `GRAPH008_JOIN_DEPTH` **292** (191 at base),
and three distinct 400-character edge kinds **1,512** with 601 for each `GRAPH003_UNKNOWN_EDGE_KIND`
above it. `describeValue` has no cap; the dedupe bounds the COUNT of distinct renderings, not the
length.

## 4 · Decisions taken without the user this wave

Nine, each recorded because nobody was asked and each is reversible only at a cost.

1. **§A.66's has-executed predicate is an ALLOWLIST (`task.leased` ∪ `gate.raised`), not a
   complement — and the complement was wrong TWICE before that.** The first cut read the FOLD, and
   a retryable failure (`task.retry_scheduled` + `task.ready`) or an ordinary `rewind` erases exactly
   that evidence: a run that had charged money read `tasks: [["pay","ready"]] gates: []` and the
   forged advance took it back. The second read "any row outside `submit`'s four-name prefix", which
   counts OPERATOR rows as execution — `pause`/`resume` append `operator.command` +
   `run.suspended`/`run.resumed` and run no node code, so pausing a run before its first advance
   bought it immunity from §A.63. **The allowlist INVERTS a property the complement had**: a
   complement reads an unrecognised row as PROGRESS (conservative); an allowlist reads it as no
   progress, so a future `EVENT_TYPES` member meaning "executed" appended before a lease would let
   the guard fail a live run. The trade was forced, and the rule that replaces the lost property is
   written at the set: *anything added to `EVENT_TYPES` that a run can append before its first
   `task.leased` belongs in `EXECUTED`.*
2. **`gate.raised` is in that set on the DIRECTION OF THE MISTAKE alone, and is held by no test.**
   The lane measured that rather than assuming it: removing it leaves the whole suite green, because
   the lease always precedes the raise — even on a run whose ENTRY NODE IS THE GATE. It stays because
   a missing member costs a LIVE RUN and a spare one costs only a refusal. Written at the site in
   both directions, so a later reader neither deletes it as dead on that evidence nor trusts a pin
   that does not exist.
3. **§A.66 was re-scoped rather than closed, and §A.63 lost a subset to do it.** Both above. If the
   maintainer wants §A.63 whole, this is the decision to revisit first — it needs a door that is not
   reachable with journal read access, which is a process boundary and not a conjunct.
4. **§A.74's two arms sit ABOVE the `planHash` check.** Reversing it gives a direct `rewind` caller
   a complaint about the authorization for a plan nobody can be shown.
5. **§H.14 wraps on a TTY only, and the `2>&1 | less` cost is paid.** Wrapping always would pay this
   row's own named cost for every piped consumer to buy the `less` case; no rule distinguishes `less`
   from `grep` at the file descriptor. The caller may reverse it.
6. **Control characters are stripped on the TTY path only, which makes a rendered file name not the
   file name.** Deliberate, because any faithful rendering of a CR on a terminal is the attack, and
   an operator who needs the true bytes has the pipe.
7. **`loom replay`'s `✗` frame writer is NOT routed through the diagnostic printer**, with the reason
   at the site: over `ReplayFrame`'s ten kinds its payloads are values an operator DIFFS — digests,
   effect keys, hashes, state names — plus exactly ONE JSON document and ONE prose sentence. The
   first cut of that reason said "two JSON documents" and was wrong about the code.
8. **§A.68 closed by the DESCRIPTION arm, on a criterion the row did not state.** The row said to
   measure `skip` and expected 1 reject + 2 approvals to meet `k: 2` while three rejections still
   failed — **both halves hold**. What the row did not predict is the third line: under `skip`, 2
   rejections + 1 approval LAND THE WRITE. `skip` would have replaced a fail-CLOSED mismatch with a
   fail-OPEN one, and *refusing is always allowed; loosening never is*. The row's literal condition
   was satisfiable and was refused anyway, on a rule the row did not carry.
9. **§A.73 ships TEN arms rather than a shorter clause.** The alternative was a clause that says less
   so fewer combinations exist; it was rejected because the information is what an author acts on,
   and the cost — a table nobody can shorten without a red suite — is the thing that makes the arms
   checkable at all.

## 5 · Facts you would otherwise rediscover

- **A byte pin covers ONE arm, so enumerate the arms BY CONSTRUCTION and assert they are DISTINCT.**
  2026-09-18 got as far as "count the arms first"; that is not enough, because a count in prose is
  a claim nobody re-runs. The `ARMS` table is the census, the loop over it is the pin, and the
  distinctness test is what catches two arms that collapsed to one string — which is how a condition
  becomes inert while every pin stays green. The lane's own design counted six; the number is ten.
- **A "pipe" test must be a pipe: `isTTY` UNDEFINED, not `false`.** A real pipe has no own `isTTY`
  property. Setting it `false` tests a state that never occurs, and the whole claim a row rests on
