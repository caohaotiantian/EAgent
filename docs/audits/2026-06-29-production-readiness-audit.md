# EAgent — production-readiness audit (2026-06-29)

_Source: 6-lens fan-out audit of the merged Waves 1–8 `init`; 40 findings → 20 confirmed gaps, 20 by-design, 0 false-positives, each verified against source. This is the Wave 9 hardening backlog's authoritative input._

# EAgent — production-readiness audit

## 1) Bottom line
EAgent is production-ready for its documented core use: a single-host, loopback, human-in-the-loop agent kernel driven from the CLI, where the seven primitives, the four core tools, and the offline test posture are solid and the marker/stub lens is clean (no TODO/FIXME/unimplemented code in `src/`). The one true blocker is in the **self-improve** extension: its sole documented safety gate (human review of candidate source) renders nothing to the reviewer in either shipped front end, so the consent prompt is blind. The single biggest structural caveat is **sub-agent governance**: several default-or-opt-in guards (flow-guard, circuit-breaker, budget-cap, output-contract, otel) are bound to the parent agent and leak or misroute when a child runs under `childScope`.

## 2) Blockers

**B1 — self-improve human-review gate shows the reviewer no source.**
`self-improve.ts:326` surfaces the candidate via `ctx.progress(...)`, but `agent.ts:525` wires `progress → logger.debug`, and both front ends silence debug (`cli.ts:146` hardcodes `debug:()=>{}`; `server.ts:85` defaults it to a no-op, and the HTTP reviewer answers via `elicit.ask` which `debug` never reaches). The `ui.ask` prompt (`self-improve.ts:327-329`) tells the operator to "Review the source above" before a `yes` calls `e.loadExtension` (`self-improve.ts:343`) → arbitrary in-process code with full `ExtensionAPI` authority. The docstring (`self-improve.ts:12-27`) and tool description (`self-improve.ts:301`) both declare source review as *the* adoption boundary, so the implementation contradicts its own design. Fail-closed mitigations exist (opt-in; `ui.ask` null → no auto-adopt at `self-improve.ts:330-331`), but when the feature is used the gate is non-functional and the prompt actively misleads.
**Fix:** render the source to a channel the operator actually sees — fold it into the `ui.ask` prompt string, or route it to `e.log.warn`/a notify sink (CLI surfaces these, `cli.ts:141`) — not `ctx.progress`. Add a test asserting the source text reaches the prompt the human sees.

## 3) Hardening

### Sub-agent / `childScope` governance leaks
Root cause: `e.agent` is bound once at activation to the parent (`extension.ts:108,:241`), and `childScope` shares filter hooks + intra-run events (incl. `usage`) by reference (`hooks.ts:36-42,167-177`); the hook context carries no acting-agent id (`events.ts:101-109`, `agent.ts:243,:474`). So guards observe child activity but can only act on the parent.
- **RW3-1 (flow-guard, default ON):** the data-taint gate reads the parent transcript `e.agent.messages` (`flow-guard.ts:164`) while the shared message handler tags the *child's* message object (`flow-guard.ts:152`); a child `read → egress` chain via `fs:read` is never held. The capability half of taint *is* child-governed (shared `tainted` Set, `flow-guard.ts:96`). Contradicts the documented intent at `hooks.ts:34`.
- **RW3-2 (steer/followUp/stop misroute):** `circuit-breaker.ts:156` (default ON) steers the parent and drops the child's de-loop; `budget-cap.ts:298`/`:280` and `output-contract.ts:170/:187` act on the parent — worst case a child's failed `respond` clobbers parent `output` and stops the parent, with shared `attempts` commingling retries. Hard enforcement still blocks the child's own call (`agent.ts:498-506`), so it is hardening, not a blocker. Cataloged as deferred RW3-2 (`DEFERRED-FOLLOWUPS.md:67`).
- **otel span mis-keying/leak:** activate-closure singletons + `openSpans` keyed by `String(turn)`/`call.id` (`otel-exporter.ts:45-47,123,140`); each fork restarts turns at 1 (`agent.ts:231`) and forks run concurrently, so `openSpans["1"]` is overwritten across forks, tool spans mis-parent, and usage upserts clobber token attrs. Even a single sequential child sub-agent overwrites the parent's open turn span. Telemetry-only.
**Fix (shared):** thread the acting agent into the hook context and have guards act on it / key spans by composite `(agent identity, turn)`; or gate these handlers to the root agent. This is the RW6b-1 / per-agent-guard-state consolidation.

### Sandbox / codeact
- **RW6c-4 — codeact readonly tier is broken (ENOENT) on Linux bwrap.** The snippet is written under `os.tmpdir()` = `/tmp` (`codeact.ts:96`) and passed as an absolute path; the bwrap branch always adds `--tmpfs /tmp` (`sandbox.ts:110`) shadowing the host `/tmp`, and only write tiers re-bind the per-call dir (`sandbox.ts:111`, `writeTier` set at `:87`). So `tier=readonly` never re-binds the snippet dir → interpreter ENOENT. Fails closed; off by default; narrow (default `TMPDIR=/tmp`); workspace-write/no-network tiers work. sandbox-exec/firejail unaffected. Pinned by `test/sandbox-tiers.test.ts:70-72`; documented deferral (`DEFERRED-FOLLOWUPS.md:129`, `README.md:204`).
  **Fix:** add `--ro-bind <dir> <dir>` for non-write tiers after `--tmpfs /tmp`, without loosening the shell readonly tier.
- **Real sandbox backends are never invoked by tests.** `wrapCommand` emits security-critical strings (SBPL `deny network*/file-write*` `sandbox.ts:97-103`; bwrap `--unshare-net/--bind` `:110-113`; firejail `--net=none/--read-write` `:117-119`) but no test runs a real binary — `sandbox-tiers.test.ts:47-99` re-asserts the implementation's own output, `codeact.test.ts:170-192` routes through a fake `echo '[[WRAPPED]]'` shim (`:177`), and `binExists` (`sandbox.ts:131-141`) has zero coverage. CI installs no sandbox tool. Residual silent risk: a flag accepted-but-non-confining passes the suite yet does not confine on a real host.
  **Fix:** add `binExists`-gated integration tests (mirroring the `python3` skip-gate at `codeact.test.ts:121`) asserting a network call fails under `no-network` and an out-of-root write fails under `workspace-write`; run one bwrap job on a Linux CI runner.

### self-improve robustness + coverage
- **execSync blocks the event loop up to ~2×120s.** `self-improve.ts:115` uses synchronous `execSync` (timeout 120s), called twice by `realEvaluate` (`:154,:155`); the async signature yields nothing. During the freeze even `/health`, `/answer`, the 409 fast-reject, and disconnect-driven `agent.stop()` stall. The inline comment "must not block the agent" (`:113-114`) is misleading. Off by default; integration-only evaluator.
  **Fix:** use `exec`/`spawn` awaited via a Promise with kill-on-timeout (AbortController) so the loop and abort stay live.
- **RW8b-2 — failed adopt-load leaves the candidate live.** `renameSync(staged→live)` at `self-improve.ts:337` runs before `e.loadExtension` at `:343`; the catch (`:344-349`) returns `fail({loaded:false})` without reverting the rename or setting `rec.status` (`status="adopted"` only on success, `:350`). `liveExtensionsDir()` is the host auto-discover dir (`host.ts:266`, `extension.ts:137-149`, no gate), so a transient load failure auto-loads the orphan next restart; retry also breaks because `stagedPath` is gone (`:320`). The reviewed source was already approved, so this is unclean-rollback/state-integrity, not a consent bypass. Low likelihood. Cataloged RW8b-2 (`DEFERRED-FOLLOWUPS.md:116`).
  **Fix:** on load failure after the rename, move the file back to staging (or write `adopted:false` + have discovery skip it).
- **`realEvaluate` is dev/source-tree-only and unexercised offline.** It builds a cwd-relative `node --import tsx src/self-improve-eval.ts` with `cwd=process.cwd()` (`self-improve.ts:111,:117/:137`), so it only resolves from the EAgent repo root under tsx — a built `dist` has no `src/...ts` and fails (caught at `:280-281`) from any other cwd (which is why `self-improve-eval.test.ts:36` forces `cwd:PROJECT_ROOT`). Every test injects a stub via `setEvaluator` (`self-improve.ts:170`; `self-improve.test.ts:98,148`), so `runScored` command assembly (`:111`), the scorecard regex (`:121`), `hashFixtures` (`:96`), the tamper diff (`:158`), and staging cleanup (`:145-167`) have zero coverage. Adoption is human-gated and the score advisory, so a regression yields a wrong advisory score, not unsafe adoption.
  **Fix:** resolve the eval-runner path from `import.meta.url` (not cwd); unit-test `runScored`'s command string and the scorecard regex against captured stdout; add a backend-gated end-to-end `realEvaluate` test.

### reasoning-search forks
- **Forks are not cancellable and orphan on abort/failure.** `reasoning-search.ts:220-221` forks up to k children via `Promise.all` with nothing wiring `ctx.signal` to `child.stop()`; `Agent.run` takes no signal (`agent.ts:215`) and each child owns its own `#abort` (`:221`). A parent `stop()` is ignored until every fork finishes; one fork rejection (`run()` rethrows, `agent.ts:334`) leaves survivors detached. The judge scorer *does* thread `ctx.signal` (`:152,:165,:179`), so the omission is inconsistent, not deliberate. Root cause is the kernel `run()` signature (same pattern in `subagents.ts:197,:239`).
- **One fork's throw fails the whole best_of_n.** Bare `Promise.all` over `child.run` (`reasoning-search.ts:221`) with no per-child try/catch discards the N-1 completed forks, while `judgeScore` is explicitly fail-soft (`:170-172`). Two retry layers precede a throw (`http.ts:84-88`, `MAX_PROVIDER_RETRIES=6` at `agent.ts:71`), and deterministic errors hit all N identically, so impact is wasted tokens of discarded successes; failure degrades to a clean error result.
  **Fix:** register an abort listener that calls each `child.stop()`; gather with `allSettled` mapping a thrown fork to an empty/zero-scored candidate; consider bounding fork concurrency.

### Accounting / provider / provenance
- **RW1-1 — per-run token budget omits cache tokens.** `limits.ts:207` sums only `inputTokens + outputTokens`; post-KDD-2 (`types.ts:206-220`) cache tokens are disjoint siblings that providers populate (`anthropic.ts:154-155`, `openai.ts:123`, `gemini.ts:112`). The cache-aware `totalTokens` helper (`types.ts:240-243`) is already used by `trace.ts:206`/`evals.ts:372`, making `limits.ts` the outlier. `maxTokensPerRun` defaults disabled (`limits.ts:32`); fail-permissive but degrades the "stop a runaway agent" guarantee exactly on heavily-cached runs.
  **Fix:** one line — sum via `totalTokens(usage)`.
- **RW6d-1 — reasoning-only assistant turn replays to empty Gemini `parts:[]`.** A mid-thought MAX_TOKENS truncation yields `content=[{thinking}]` (`gemini.ts:147`), pushed unconditionally into `#messages` (`agent.ts:250`) and captured by snapshot/restore; on replay `toGeminiContents` drops the thinking block and still `out.push({role,parts:[]})` (`gemini.ts:208`), which `generateContent` rejects (400). The design comment at `gemini.ts:145-146` holds for thinking+text/tool turns but not this edge. Gemini-only; requires truncation + snapshot/restore replay.
  **Fix:** in the request builders, drop (or stub with a placeholder text part) any assistant message whose replay yields empty content.
- **provenance gate scans only top-level string args.** `provenance.ts:99-100` iterates `Object.values` at top level and `continue`s on non-strings, never inspecting string leaves in nested objects/arrays; `mcp:call` is a default sink (`:40,:42`) and MCP tools register arbitrary nested JSON-Schema params (`mcp.ts:509-512`), so structured untrusted args bypass the gate. Off by default; best-effort CaMeL-lite heuristic (already verbatim-only), so defense-in-depth, not a hard boundary. Blind spot undocumented (docstring says "string args", `:17,:92`).
  **Fix:** recursively walk string leaves of nested args, or explicitly document the top-level-only limit.

### HTTP server
- **Non-loopback bind + empty token is only warned, never refused.** `yolo` defaults true (`server.ts:108`) → `fallback:"allow"` auto-grants every capability (`host.ts:214`, `capabilities.ts:102`); token defaults `""` and auth is enforced only `if (security.token …)` (`server.ts:186`). Default bind is `127.0.0.1` (`server.ts:407`) so the default is not network-reachable and the combination is documented yolo posture — but the dangerous combo (`EAGENT_HOST=0.0.0.0` + unset token) is only warned (`server.ts:123-128`).
  **Fix:** refuse to bind a non-loopback address when `EAGENT_TOKEN` is empty (fail-closed on the dangerous combination).

## 4) By-design / accepted
- **RW5-1 — fallback-routing not migrated to the `onProviderError` seam.** The seam is same-provider retry + model downshift only (no provider field, `events.ts:119-122`, `agent.ts:347/:431`); cross-provider failover stays in the composite wrapper (`fallback-routing.ts:195-230`). Both ship; explicitly deferred (`DEFERRED-FOLLOWUPS.md:81-87`).
- **No TODO/FIXME/HACK/stub in `src/`.** Marker lens is clean; all hits are live extensions/prompt tokens/test hooks; production `realEvaluate` is fully implemented (`self-improve.ts:132-168`).
- **self-improve eval fail-closed when no sandbox backend.** `realEvaluate` throws on `detectBackend()=="none"` (`self-improve.ts:134`), caught into a clean `fail()` (`:280-282`); the correct posture for running untrusted candidate code. macOS always has `sandbox-exec`.
- **self-improve adoption runs adopted code in-process with full authority.** Documented (`self-improve.ts:25-27`); gated by `ui.ask` that is null (fail-closed) when non-interactive/HTTP (`cli.ts:127/:134`, `server.ts:105`), unlike `confirm` which auto-approves under `--yolo`.
- **vetoCandidate static filter is trivially evadable.** Declared a pre-filter, not a boundary (`self-improve.ts:17-19,70-73`); a pass only writes to staging, never executes.
- **codeact runs model-authored code unsandboxed by default (tier=off).** Subprocess is an explicitly weak boundary / documented sandbox seam (`codeact.ts:9-24`); `code:exec` not auto-granted (`:176-179`); HTTP yolo is the weakest documented config (`SECURITY.md`).
- **secret-guard is a narrow, decode-blind, fail-open regex pre-filter.** All limits are documented decisions (`docs/design/2026-06-22-secret-guard.md:184-201,266-268,349-353`); framed as a "prevention seam", never a boundary.
- **sandbox-tiers `no-network` does not confine in-process `net:fetch`; grandchild signal delivery is best-effort.** Hook is `shell:exec`-scoped (`sandbox-tiers.ts:110-111`); documented (`:38-45`); structural property of process sandboxing.
- **sandbox-tiers fails OPEN on a missing backend by default.** Deliberate ("a degraded environment must not brick the agent", `sandbox-tiers.ts:130`), test-pinned (`test/sandbox-tiers.test.ts:219-235`), documented (`ROADMAP.md:73`); best-effort layer over an already-authorized tool; codeact's fail-closed default is intentional differentiation. Residual nit: warn-once-per-session staleness (`:147-151`).
- **RW4-2 — HTTP server shares the capability audit log + namespaced Store across sessions.** Store is process-persistent by design (`store.ts:4-6`); single-flight serializes turns (no race); audit log never exposed. Residual: "session" isolation is transcript-only and undocumented; `DELETE /sessions/:id` drops only the snapshot, not Store writes.
- **beforeDispatch wave is not de-duplicated.** Documented as the handler's job (`docs/design/2026-06-29-before-dispatch.md:61-65`, `EXTENSIONS.md:323-334`); the `originalCalls.map` reconciliation guarantees one tool_result per id, so no provider 400. No built-in uses `beforeDispatch`.
- **reasoning-search prune can yield two consecutive user turns.** The dangling-tool_use prune (`reasoning-search.ts:117-123`) is necessary; current providers merge same-role turns. Off by default. (Residual: undocumented side effect; Gemini tolerance unverified; no offline regression guard since MockProvider doesn't validate role alternation.)
- **No live provider HTTP path is exercised.** Offline-by-design (CLAUDE.md); wire-format/retry/SSE are unit-tested with synthetic streams; the cassette only ever wraps MockProvider. (Residual minor: no opt-in API-key-gated smoke or real-provider cassette to catch endpoint/auth/SSE-framing regressions.)
- **cost extension uses fixed cache multipliers and does not separately price reasoning tokens.** Anthropic-standard rates (`cost.ts:108-109`); reasoning is a subset-of-output per the maintained contract (`types.ts:210-212`, `gemini.ts:116-118`, `openai.ts:124-127`); explicitly advisory/observability-only (`cost.ts:9,68,104-106`).

## 5) Minor
- otel-exporter drops the final span batch on hard-exit: `flush()` is fire-and-forget and the `session_shutdown` handler doesn't await it (`otel-exporter.ts:84,96,192`). Affects SIGINT/SIGTERM/server-shutdown (`process.exit`), not the natural CLI exit. Fix: return/await the fetch promise. Telemetry-only.
- sandbox-exec SBPL profile interpolates `root` unescaped into `(subpath "${root}")` (`sandbox.ts:99-100`) while bwrap/firejail `shquote` it; a path with `"`/`\` yields a malformed profile (fails closed). `root` is operator-controlled. Fix: escape `"`/`\`.
- self-improve `evaluate_candidate` declares no capability (`self-improve.ts:258-295`) while `propose`/`adopt` declare `self:extend`; it spawns a subprocess that runs the staged candidate, so no ask-prompt and no audit entry at the first code-execution point. Fix: declare `code:exec` (or `self:extend`).
- time-travel `/checkpoint` calls `e.agent.snapshot()` un-guarded (`time-travel.ts:208`) while the auto/fork paths wrap it; and `readBlob` (`:78`)/`restore` (`agent.ts:203-213`) apply a parsed blob without the shape validation `session.ts:237-249` uses. Off by default; machine-written blobs. Fix: wrap the snapshot and add a minimal shape check.
- memory `consolidate` "keep earliest" actually keeps first-by-key-iteration, not earliest-by-ts (`memory.ts:261-274`): an overwrite bumps `ts` without changing key insertion order, so it can delete the genuinely earliest copy. A `lowestByTs` helper exists (`memory.ts:148-159`) but is unused here; the test asserts only count (`test/memory.test.ts:276-295`). Fix: select by lowest `ts`, or soften the comment.
- self-improve-eval entrypoint is tested only unsandboxed (`test/self-improve-eval.test.ts:33`): nothing exercises entrypoint + `wrapCommand` + confinement together. Fail-closed; advisory; offline-by-design. Fix: optional backend-gated test running the entrypoint through `wrapCommand(detectBackend(...), "no-network", ...)`.
